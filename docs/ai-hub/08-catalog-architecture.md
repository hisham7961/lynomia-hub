## ٠) المبدأُ الحاكمُ للكتالوج كلِّه

**[C]** صورةُ LiteLLM المثبّتةُ تحوي **١٣٥ مُحَوِّلَ مزوّد** (`litellm/llms/*/`)،
و**خريطةَ أسعارٍ وحدودٍ وقدراتٍ** مرفقةً
(`litellm/model_prices_and_context_window_backup.json`)، و**مُشتقَّ وسائطَ
مدعومةٍ لكلِّ نموذج** (`litellm_core_utils/get_supported_openai_params.py`).

**[P] فالاستنتاجُ الحاسم:**

> **كلُّ معرفةٍ عن «كيف نتحدّث إلى مزوّد» موجودةٌ في LiteLLM. وكلُّ معرفةٍ عن
> «ماذا نختار ومن يملك الإذن وكيف نعرضه» مكانُها Hub.**
>
> وأيُّ سطرٍ في Hub يعرف أنّ OpenAI يحتاج `OPENAI_API_KEY` **عيبٌ معماريّ**:
> تكرارٌ لمعرفةٍ يملكها غيرُنا ويحدّثها غيرُنا.

فالكتالوجُ **ليس نسخةً من LiteLLM** — بل **قائمةُ ما التزمنا بدعمِه، ومخطَّطُ
ما نسأل المستخدمَ عنه**. لا أكثر.

## ١) مخطَّطُ المزوّد — `config/ai_catalog.php`

### الشكل

```php
'openai' => [
    'label'        => 'OpenAI',
    'label_en'     => 'OpenAI',
    'icon'         => 'openai',              // مفتاحٌ في مجموعةِ الأيقوناتِ لا رابطٌ خارجيّ
    'litellm_key'  => 'openai',              // المعرّفُ الرسميُّ عند LiteLLM
    'auth'         => 'api_key',             // api_key | api_key_endpoint | cloud_iam | oauth
    'docs_url'     => 'https://docs.litellm.ai/docs/providers/openai',
    'discovery'    => 'gateway',             // gateway | provider_api | catalog_only | manual
    'test'         => 'test_connection',     // كيف يُختبَر الاعتماد
    'fields'       => [ /* §٢ */ ],
],
```

### لماذا هذه الحقولُ بعينِها

| الحقل | لماذا |
|---|---|
| `label` / `label_en` | العرضُ عربيٌّ أوّلاً والمعرّفاتُ التقنيّةُ إنجليزيّة |
| `icon` | **مفتاحٌ داخليٌّ لا رابطُ CDN** — رابطٌ خارجيٌّ يعني طلباً يغادر الشبكةَ من صفحةِ إدارة |
| `litellm_key` | جسرُ الترجمةِ الوحيدُ بين لغتِنا ولغةِ البوّابة |
| `auth` | يحدّد **شكلَ** الإدخالِ لا الحقولَ نفسَها |
| `discovery` | **[P]** هل النماذجُ تُكتشَف؟ وكيف؟ (§٨) |
| `test` | أيُّ آليّةٍ تثبت أنّ الاعتمادَ يعمل |

**ولا `enabled` في الكتالوج** — التفعيلُ خاصّيّةُ **اتّصال** لا **نوع**. مكانُه
`ai_providers.enabled`.

## ٢) مخطَّطُ الإدخالِ الديناميّ — لا نموذجَ مكتوبٌ يدويّاً لكلِّ مزوّد

### الاكتشافُ الذي يوفّر بناءَ طبقةٍ كاملة

**[C]** المستودعُ **يملك هذه الآليّةَ عاملةً منذ سنوات**: `config/hub.php` يعرّف
**١٬٥٨٩ حقلاً** بالشكل
`['key','col','label','type','required','options','hint','min','rules','default']`
ويبنيها المحرّكُ ديناميّاً.

**[P] فمخطَّطُ إدخالِ المزوّدِ هو هذا الاصطلاحُ نفسُه + أربعةُ مفاتيحَ لا خامس:**

| مفتاحٌ جديد | لماذا لزم |
|---|---|
| `secret` | يحكم: `type=password` · لا يعود إلى المتصفّح · لا يدخل تدقيقاً ولا سجلّاً |
| `show_if` | الحقلُ الشرطيّ (`api_version` لا يظهر إلّا لـAzure) |
| `placeholder` | شكلُ القيمةِ المتوقَّع — **ولا يحمل قيمةً حقيقيّة** |
| `sends_to` | **المفتاحُ المعماريُّ**: `credential` (يذهب إلى خزنةِ LiteLLM) أو `config` (يُحفَظ في `ai_providers.config` بلا تشفير) |

> **`sends_to` هو ما يجعل الفصلَ آليّاً لا اجتهاديّاً.** فالنظامُ لا «يتذكّر» أنّ
> `api_key` سرٌّ و`base_url` ليس: **المخطَّطُ يقولها**، والمحرّكُ يوجّه كلَّ حقلٍ
> إلى وجهتِه بلا قرارٍ بشريٍّ يُنسى.

### مثالٌ — الحقلُ الواحد

```php
[
    'key'         => 'api_version',
    'label'       => 'إصدار الواجهة',
    'type'        => 'text',
    'required'    => true,
    'secret'      => false,
    'sends_to'    => 'config',
    'placeholder' => 'YYYY-MM-DD',
    'rules'       => ['regex:/^\d{4}-\d{2}-\d{2}(-preview)?$/'],
    'show_if'     => ['auth' => 'api_key_endpoint'],
    'hint'        => 'مطلوبٌ لنشرِ Azure — تجده في صفحةِ النشرِ لديك.',
]
```

### الثوابتُ المفروضةُ باختبارٍ يفشل أوّلاً

1. كلُّ حقلٍ `secret=true` ⇒ `type` = `password` **و**`sends_to` = `credential`.
2. لا حقلَ `secret=true` يظهر في أيِّ ردِّ HTML أو JSON — ولا قناعُه.
3. لا حقلَ `secret=true` يدخل حمولةَ `hub_audit` — **اسمُه فقط**.
4. `sends_to=config` **لا يقبل** `secret=true` — تناقضٌ يُرفَض عند التحميل.
5. كلُّ `show_if` يشير إلى مفتاحٍ موجودٍ فعلاً.

### حالةُ السرِّ المعروضة — ثلاثيّةٌ لا ثنائيّة

| الحالة | متى | ما يُعرَض |
|---|---|---|
| `missing` | لا اعتمادَ عند البوّابة | «غيرُ مُهيَّأ» |
| `configured` | الاعتمادُ محفوظٌ ولم يُختبر | «مُهيَّأٌ — لم يُختبر» |
| `verified` | الاختبارُ نجح على البصمةِ الحاليّة | «مُهيَّأٌ ومُختبَر · قبلَ ١٢ دقيقة» |
| `rejected` | المزوّدُ ردّ 401/403 | «المزوّدُ رفض الاعتماد» |

> **🔴 تصحيحُ W0:** قلتُ هنا «ولا قناعَ إطلاقاً، فـHub لا يملك القيمةَ فلا
> يستطيع تقنيعَها». **والفصلُ صحيحٌ والاستنتاجُ كان ناقصاً.**
>
> **[C]** ‏`credential_endpoints/endpoints.py:128–136,159–167` — البوّابةُ نفسُها
> تُقنِّع قيمَ الاعتمادِ عند القراءة (`_get_masked_values(..., unmasked_length=4)`).
> **فـHub لا يملك السرَّ، ويستطيع رغم ذلك عرضَ قناعٍ صادقٍ لأنّ البوّابةَ
> تُعطيه مُقنَّعاً.**
>
> فالعرضُ يصير: «مُهيَّأ · ‏••••abcd» — تجربةٌ أفضلُ بلا تنازلٍ أمنيٍّ واحد.
> والتفصيلُ في `09-w0-management-contract.md` §١‑أ.

## ٣) مخطَّطُ النموذج

الحقولُ في `ai_models` (§15 من التقرير). وما يهمُّ هنا **من أين يأتي كلُّ حقل**:

| المجموعة | الحقول | المصدر |
|---|---|---|
| الهويّة | `litellm_model_name` · `upstream_model` · `provider_id` | Hub (المستخدمُ أو الاكتشاف) |
| العرض | `display_name` · `family` · `version` · `tags` · `priority` | Hub |
| الحوكمة | `enabled` · `created_by` · `updated_by` | Hub |
| **المعرفة** | `capabilities` · `limits` · `params` · `pricing` | **خريطةُ LiteLLM — مُخزَّنةٌ نسخاً مؤقّتاً** |
| القياس | `health` · `last_probe_at` · `last_latency_ms` · `last_error` | الفحص |

> **[P] «مُخزَّنةٌ نسخاً مؤقّتاً» قرارٌ مقصود:** المعرفةُ تُقرأ من البوّابةِ
> وتُحفَظ في Hub **لتسريعِ العرضِ وحده**، وتُختَم بـ`source` و`fetched_at`،
> **وقابلةٌ للحذفِ وإعادةِ البناءِ بلا فقدِ شيء**. فهي ليست مصدرَ حقيقةٍ ثانياً.

## ٤) مخطَّطُ القدرات — ثلاثيٌّ بمصدر

### الشكل

```json
"capabilities": {
  "chat":              { "v": true,  "src": "litellm" },
  "streaming":         { "v": true,  "src": "litellm" },
  "tools":             { "v": true,  "src": "verified", "at": "2026-09-20T10:14:00Z" },
  "structured_output": { "v": true,  "src": "litellm" },
  "vision":            { "v": null,  "src": "unknown"  },
  "reasoning":         { "v": false, "src": "litellm" },
  "audio_in":          { "v": null,  "src": "unknown"  },
  "embeddings":        { "v": false, "src": "litellm" },
  "batch":             { "v": null,  "src": "unknown"  }
}
```

### ‏`src` — أربعُ درجاتٍ مرتّبةُ الثقة

| `src` | معناه | تُكتب متى |
|---|---|---|
| `litellm` | من خريطةِ الحزمةِ المرفقة | عند الاستيراد |
| `provider` | من واجهةِ المزوّدِ نفسِه | إن أتاحها |
| `verified` | **اختبارُ قدرةٍ حقيقيٌّ نجح (المستوى E)** | بعد الاختبارِ وحدَه |
| `hub_override` | المديرُ قرّرها يدويّاً | **تعلو الكلَّ ولا تُدهَس بالتحديث** |
| `unknown` | **لا دليل** | الافتراضُ عند غيابِ كلِّ ما سبق |

### القائمةُ الكاملة
`chat` · `text` · `reasoning` · `vision` · `image_generation` · `audio_in` ·
`audio_out` · `speech_to_text` · `text_to_speech` · `video` · `embeddings` ·
`reranking` · `tools` · `structured_output` · `streaming` · `batch` ·
`fine_tuning`

**ولا قدرةَ تُستنتَج من اسمِ نموذجٍ إطلاقاً.** الاسمُ نصٌّ من المزوّد، لا عقدٌ.

## ٥) مخطَّطُ الوسائط — المدخلاتُ التي يقبلها النموذجُ فعلاً

**[C]** المصدرُ الطبيعيُّ `get_supported_openai_params.py` في الحزمة.
**[C] فجوة G1:** أَتُعرَض عبر HTTP أم تُقرأ من بياناتِ `/model/info`؟ **تُغلَق في
‏W0 قبل أيِّ بناء.**

### الشكل

```json
"params": {
  "temperature":       { "supported": true,  "type":"float","min":0,"max":2,"default":1,   "src":"litellm" },
  "top_p":             { "supported": true,  "type":"float","min":0,"max":1,"default":1,   "src":"litellm" },
  "max_tokens":        { "supported": true,  "type":"int",  "min":1,"max":16384,           "src":"litellm" },
  "reasoning_effort":  { "supported": false,                                               "src":"litellm" },
  "response_format":   { "supported": true,  "type":"enum","allowed":["text","json_object","json_schema"], "src":"litellm" },
  "tools":             { "supported": true,  "type":"array",                               "src":"verified" },
  "tool_choice":       { "supported": true,  "type":"enum","allowed":["auto","none","required"], "src":"litellm" },
  "seed":              { "supported": null,                                                "src":"unknown" },
  "stop":              { "supported": true,  "type":"array","max_items":4,                 "src":"litellm" }
}
```

### الثابتُ الأهمُّ في هذه الوثيقة

> **وسيطٌ `supported ≠ true` لا يُعرَض في الواجهةِ ولا يُرسَل إلى البوّابةِ
> إطلاقاً.**
>
> و`null` (غيرُ معروف) **يُعامَل معاملةَ غيرِ المدعوم عند الإرسال** — لأنّ
> إرسالَ وسيطٍ مجهولِ الدعمِ يُنتج ٤٠٠ في أحسنِ الأحوال، وسلوكاً صامتاً مختلفاً
> في أسوئِها.
>
> **لكنّه يُعرَض في التشخيصِ بوصفِه «غيرَ معروف» لا «غيرَ مدعوم»** — فالفرقُ
> بينهما هو الفرقُ بين «لم نفحص» و«فحصنا فلم يدعم» (§12).

> **[C] وحزامٌ ثانٍ عند البوّابة:** `drop_params: true` في
> `deploy/litellm/config/litellm-config.yaml` — فلو تسرّب وسيطٌ غيرُ مدعومٍ
> أسقطته البوّابةُ بدل إسقاطِ الطلب. **حزامٌ لا بديلٌ عن الحارسِ في Hub.**

| `src` | الثقة | التحديث |
|---|---|---|

1. **لا سعرَ ثابتٌ في شيفرةِ Hub** — المصدرُ المرفقُ بالحزمةِ موجودٌ ويتحدّث.
2. **العملةُ والوحدةُ تُخزَّنان دائماً** — رقمٌ بلا وحدةٍ كذبةٌ تنتظر.
3. **الشاشةُ تكتب «تقديريّة»** — ‏[C] الحسابُ من خريطةٍ لا من فاتورةِ المزوّد.
   وإخفاءُ هذا القيدِ يجعل الشاشةَ تكذب.

## ٨) استراتيجيّةُ الاكتشاف

### أربعةُ مصادرَ — ولكلٍّ حدُّه

| المصدر | يعطي | لا يعطي | الوسم |
|---|---|---|---|
| **`GET /v1/models` من البوّابة** [C] | ما **سُجِّل عندنا** | النماذجَ التي لم نُسجّلها | `gateway` |
| **واجهةُ المزوّدِ عبر البوّابة** | ما يتيحه **حسابُك** فعلاً | متفاوتٌ بين المزوّدين | `provider_api` |
| **خريطةُ LiteLLM المرفقة** [C] | أسماءً وقدراتٍ وحدوداً وأسعاراً | ما يتيحه حسابُك | `catalog` |
| **إضافةٌ يدويّة** | أيَّ شيء | تحقّقاً | `manual` |

> ⚠️ **و`/v1/models` وحدَه لا يكفي — وهذا مُثبَتٌ لا مُفترَض:** بوّابتُنا الآن
> تردّ **[R]** `model_count = 0` والحسابُ لم يُربَط بعد. فالمسارُ يقول «ما
> سجّلناه» لا «ما يتيحه المزوّد».

### المسارُ المقترح — **مُقيَّمٌ وموافَق**

```
مزوّدٌ متّصل → اكتشاف → مراجعة → اختيار → تهيئة → اختبار → تفعيل
```

**تقييمي: صحيحٌ ويُعتمَد، لسببين:**

1. **«الاكتشافُ لا يُفعِّل»** ينفي الخطرَ الأكبر: حسابٌ يتيح ٦٠ نموذجاً
   فتُفعَّل كلُّها تلقائيّاً، فيُوجَّه طلبٌ إلى نموذجٍ باهظٍ لم يختره أحد.
2. **«التهيئةُ قبل الاختبار»** ضروريّة: اختبارُ نموذجٍ بلا وسائطَ صحيحةٍ يُنتج
   فشلاً كاذباً يُطارَد ساعةً.

**وإضافةٌ واحدةٌ أقترحُها:** خطوةُ **المراجعة** تُظهر لكلِّ نموذجٍ مُكتشَفٍ
**ما نعرفه وما نجهله** قبل الاختيار — فيختار المديرُ عالماً بأنّ قدراتِ هذا
النموذجِ `unknown` مثلاً. الاختيارُ الأعمى يُنتج توجيهاً أعمى.

## ٩) واجهةٌ تقودها القدرات

### القاعدة

> **ما لا يدعمه النموذجُ لا يُرسَم.** ولا نموذجَ إعداداتٍ واحدٌ يُعرَض لكلِّ
> النماذجِ ثمّ تُطفأ بعضُ حقولِه.

### الاشتقاق

```
capabilities + params  →  الأقسامُ المرئيّة  →  الحقولُ المرئيّة  →  مدياتُها
```

| القدرة | ما يظهر |
|---|---|
| `chat` أساساً | الحرارةُ · `top_p` · أقصى المخرَج · إيقاف |
| `reasoning` = `true` | **قسمُ الاستدلال** — `reasoning_effort` بالقيمِ المدعومةِ **وحدَها** |
| `reasoning` = `true` و`temperature.supported` = `false` | **الحرارةُ تختفي** — وكثيرٌ من نماذجِ الاستدلالِ لا تقبلها |
| `vision` = `true` | حدودُ الصورِ وأنواعُها |
| `structured_output` = `true` | `response_format` بالقيمِ المسموحةِ وحدَها |
| `tools` = `true` | `tool_choice` · الاستدعاءُ المتوازي |
| `image_generation` = `true` | المقاسُ والجودةُ والعدد |
| **أيُّ قدرةٍ `null`** | **لا يظهر قسمُها** · وسطرٌ في التشخيص: «غيرُ معروف — يُثبَت باختبارِ المستوى E» |

**وثابتٌ يُختبَر:** عرضُ صفحةِ تهيئةٍ لنموذجٍ قدراتُه كلُّها `unknown` **لا يُنتج
حقلاً واحداً** غيرَ الهويّةِ والحالة. وصفحةٌ تعرض حقولاً لا يدعمها النموذجُ عيبٌ
يُبلَّغ.

## ١١) استراتيجيّةُ التحديث

### ستُّ حالاتٍ وردُّ النظامِ على كلٍّ منها

| الحدث | الكشف | الردّ — **ولا كسرَ للتوجيه** |
|---|---|---|
| **نموذجٌ جديدٌ لدى المزوّد** | اكتشافٌ يدويّ | يظهر «جديدٌ — غيرُ مُفعَّل». **لا أثرَ على التوجيه** |
| **نموذجٌ أُهمل** | اختفى من الاكتشافِ أو 404 | يُوسَم `deprecated` · تحذيرٌ إن كان في سلسلةِ توجيه · **يبقى يعمل حتّى يفشل** |
| **نموذجٌ أُعيدت تسميتُه** | الاسمُ القديمُ 404 والجديدُ يظهر | **لا مطابقةَ تلقائيّةً** — يُعرَض اقتراحُ ربطٍ للمراجعة. والمطابقةُ الآليّةُ بالاسمِ تُنتج توجيهاً إلى نموذجٍ لم يختره أحد |
| **السعرُ تغيّر** | مقارنةٌ بعد التحديث | يُحدَّث ما `src != hub_override` · **فرقٌ يتجاوز عتبةً ⇒ إشعارٌ للمدير** |
| **قدرةٌ تغيّرت** | مقارنة | `unknown → true` تُقبَل · **`true → false` تُوقِف التوجيهَ المشروطَ بتلك القدرةِ وتُبلِّغ** |
| **نافذةُ السياقِ تغيّرت** | مقارنة | تُحدَّث · **النقصانُ يُبلَّغ** إذ قد يكسر طلباتٍ كانت تمرّ |

### الثابتُ الحاكم

> **التحديثُ يغيّر المعرفةَ ولا يغيّر القرار.** فلا يُفعِّل نموذجاً، ولا يُعطّله،
> ولا يُبدّل أساسيّاً، ولا يمسّ سلسلةَ احتياط. **قرارُ التوجيهِ للمديرِ وحدَه.**
>
> والاستثناءُ الوحيد: قدرةٌ سقطت إلى `false` وملفٌّ يشترطها ⇒ **يُوقَف ذلك
> المسارُ ويُبلَّغ**، إذ إبقاؤه يعني فشلاً مضموناً عند كلِّ طلب.

**ولا مجدولَ في المرحلة ٢** — زرُّ «تحديثٌ الآن» يدويٌّ ومُدقَّق. والجدولةُ
تُضاف لاحقاً بلا تغييرِ شيءٍ ممّا سبق.

## ١٢) `Unknown` ≠ `Unsupported`

### لماذا هذا مبدأٌ لا تفصيل

**[C] المستودعُ حسم هذا سلفاً:** `ConnectionProbe::SHAPE` جعل `up` ثلاثيّاً
(`null` = لم يُجرَّب · `true` · `false`)، و`AiGateway::whyNotReady()` تفرّق
«غيرَ مهيّأ» عن «مطفأ» عن «فاشل». **فالكتالوجُ يرث المبدأَ لا يخترعُه.**

### الثلاثيّةُ في أربعةِ مواضع

| الموضع | `true` | `false` | `null` |
|---|---|---|---|
| القدرة | مدعومة | **ثبت** عدمُ الدعم | **لا دليل** |
| الوسيط | يُعرَض ويُرسَل | يُخفى ولا يُرسَل | **يُخفى ولا يُرسَل — ويُقال «غيرُ معروف»** |
| الحدّ | رقمٌ موثوق | — | «غيرُ معلوم» |
| السعر | رقمٌ موثوق | — | «غيرُ معلوم» |

### السلوكُ عند `null` — قاعدتان تبدوان متناقضتين وليستا

1. **عند التنفيذ: `null` يُعامَل معاملةَ `false`** — لا يُرسَل، ولا يُرقَّى نموذجٌ
   إلى ملفٍّ يشترط قدرةً مجهولة. **الحذرُ افتراضٌ آمن.**
2. **عند العرضِ والتشخيص: `null` يبقى `null`** — «غيرُ معروف» مع زرِّ «أثبِتها
   باختبار».

> **ولمَ الفرقُ؟** لأنّ خلطَهما يُنتج عيبين متقابلين: معاملةُ `null` معاملةَ
> `true` تُرسِل وسيطاً غيرَ مدعومٍ فيفشل الطلب؛ **وعرضُ `null` بوصفِه `false`
> يُغلق باباً مفتوحاً**، فيظنُّ المديرُ أنّ النموذجَ لا يدعم الرؤيةَ وهو يدعمها،
> فيشتري نموذجاً ثانياً بلا حاجة. **الأوّلُ عطلٌ يُرى، والثاني خسارةٌ لا تُرى.**

## ١٧) إضافةُ مزوّدٍ جديدٍ لاحقاً — **مدخلُ مصفوفةٍ واحد**

```
مدخلٌ في config/ai_catalog.php  →  انتهى.
```

**ولا شيءَ غيرُ ذلك:** لا هجرة · لا متحكّم · لا قالب · لا مسار · لا صلاحيّة ·
لا اختبارٌ جديد.

| الطبقة | ماذا تحتاج؟ | لماذا |
|---|---|---|
| النقلُ إلى المزوّد | **لا شيء** | **[C]** ‏١٣٥ مُحَوِّلاً في الصورة |
| نموذجُ الإدخال | **لا شيء** | يُبنى من `fields` (§2) |
| التخزين | **لا شيء** | `ai_providers` عامٌّ بـ`catalog_key` + `config` json |
| الاعتماد | **لا شيء** | `sends_to` يوجّه كلَّ حقلٍ آليّاً |
| الاختبار | **لا شيء** | `test_connection` واحدٌ للجميع |
| الصلاحيّة | **لا شيء** | `aiAdmin` يحكم النوعَ كلَّه |
| الواجهة | **لا شيء** | الكتالوجُ يُعرَض حلقةً |

**ويبقى ما يحتاج شيفرةً — وهو نادرٌ ويُقال:**
- مزوّدٌ بمصادقةٍ ليست `api_key` ولا `api_key_endpoint` (مثل اعتمادِ سحابةٍ
  متعدّدِ الحقولِ بتوقيع) ⇒ **نوعُ `auth` جديدٌ** يُضاف مرّةً ويخدم كلَّ نظائرِه.
- مزوّدٌ يملك اكتشافاً خاصّاً ⇒ مُكتشِفٌ يُضاف تحت `discovery`.

> **وحتّى هاتان توسعتان لنوعٍ لا حالةٍ خاصّةٍ لمزوّدٍ بعينِه.** واللحظةُ التي
> يظهر فيها `if ($provider === 'openai')` في شيفرةِ Hub هي اللحظةُ التي انكسر
> فيها هذا التصميم.

## ١٨) ظهورُ نموذجٍ جديدٍ لاحقاً — **بلا إعادةِ تصميم**

### المسار

```
ترقيةُ صورةِ LiteLLM  →  خريطةُ الأسعارِ والقدراتِ تحمل الجديد
   أو
«اكتشِف الآن» في الواجهة  →  النموذجُ يظهر «جديدٌ — غيرُ مُفعَّل»
   ↓
مراجعةٌ (ماذا نعرف · ماذا نجهل) → اختيار → تهيئة → اختبار → تفعيل
```

### لماذا لا ينكسر شيء

| لأنّ… | فـ… |
|---|---|
| النموذجُ **صفٌّ** لا صنفٌ ولا ثابتٌ في الشيفرة | لا دفعةَ شيفرةٍ لنموذجٍ جديد |
| القدراتُ **بيانات** لا `if` | قدرةٌ جديدةٌ = مفتاحٌ جديدٌ في `capabilities` |
| الوسائطُ **بيانات** | وسيطٌ جديدٌ يظهر بلا تعديلِ نموذجِ إدخال |
| الواجهةُ **تُشتقّ** | حقلٌ جديدٌ يُرسَم تلقائيّاً |
| التوجيهُ يشير بـ**المعرّف** | نموذجٌ جديدٌ لا يمسّ سلسلةً قائمة |
| `unknown` هو الافتراض | حقلٌ لم نعرفه **لا يكذب** |
| **الاكتشافُ لا يُفعِّل** | ظهورُ نموذجٍ لا يغيّر سلوكاً |

### الحدُّ الصريح — ما **يحتاج** عملاً

| الحالة | العمل |
|---|---|
| **قدرةٌ لم توجد قطّ** (وسيطُ إدخالٍ جديدٌ كلّيّاً) | مفتاحٌ في قائمةِ القدرات + قسمٌ في الواجهة — **مرّةً واحدةً للقدرةِ لا للنموذج** |
| **نوعُ وسيطٍ لا يمثّله المخطَّط** (كائنٌ متشعّب) | توسعةُ أنواعِ المخطَّط — **مرّةً واحدة** |
| **تسعيرٌ بوحدةٍ جديدة** (بالثانيةِ مثلاً) | وحدةٌ جديدةٌ في مخطَّطِ السعر |

**والعامَّةُ هنا هي المقصودة:** العملُ يُبذَل **للقدرةِ الجديدة** لا **للنموذجِ
الجديد**. فعشرةُ نماذجَ تحمل القدرةَ نفسَها تُستوعَب بصفرِ عمل — وهذا هو الفرقُ
بين نظامٍ يتقادم ونظامٍ يعيش.

## خلاصةُ هذا القسم

| السؤال | الجواب |
|---|---|
| أين معرفةُ «كيف نتحدّث»؟ | **LiteLLM** — ‏١٣٥ مُحَوِّلاً |
| أين معرفةُ «ماذا نعرض ونسأل»؟ | **كتالوجُ Hub** — ملفُّ إعدادٍ في Git |
| أين السرّ؟ | **LiteLLM حصراً** — وHub ناقلٌ لا خزنة |
| كيف يُضاف مزوّد؟ | **مدخلُ مصفوفةٍ واحد** |
| كيف يظهر نموذجٌ جديد؟ | اكتشافٌ ← مراجعةٌ ← تفعيلٌ يدويّ |
| ما الافتراضُ عند الجهل؟ | **`unknown`** — لا `false` ولا تخمين |
| متى نقول «مدعوم»؟ | حين يقولها مصدرٌ موسوم — **وحين نختبرُها لقدرةٍ حرجة** |

**STOP. التصميمُ جاهزٌ للمراجعة — ولا تنفيذ.**
