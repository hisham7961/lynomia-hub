# دليلُ تشغيلِ مسارِ الذكاء — النشرُ والتراجعُ واليومُ العاديّ

> **المرحلة ٥ · W11 + W6.** وهذا الدليلُ **يُضاف إلى** `docs/RUNBOOKS.md`
> ولا يُبدّله: كتيّباتُ المنصّةِ العامّةُ هناك (القاعدة · التخزين · النشرُ
> الفاشل · النسخ)، وهنا **ما يخصُّ مسارَ الذكاءِ وحدَه**.

---

## ٠) قبل كلِّ شيءٍ — ما لا يُفعَل أبداً

| ممنوعٌ | السبب |
|---|---|
| `git clean -fd` على الإنتاج | يمحو `error_log` و`public/storage` و`.env` غيرَ المتعقَّبة |
| `git reset --hard` بلا نسخةٍ سابقة | تغييرٌ محلّيٌّ مشروعٌ يُمحى بلا أثر |
| `docker compose down -v` | **يمحو `litellm_pgdata`** — كلُّ الاعتماداتِ والنماذج |
| حذفُ `/etc/litellm` | إعدادُ البوّابةِ ومرساةُ تشفيرِها |
| تغييرُ `LITELLM_SALT_KEY` | اعتماداتُ المزوّدين تصير **حاضرةً لا تُفَكّ** |
| تغييرُ `APP_KEY` | إعداداتُ Hub المشفَّرةُ والنسخُ المشفَّرةُ تصير غيرَ مقروءة |
| إدخالُ سرِّ مزوّدٍ من الطرفيّة | يبقى في `~/.bash_history` وفي سجلّاتِ العمليّات |

**ومفتاحا `LITELLM_SALT_KEY` و`APP_KEY` لا يُعرَضان في أيِّ مخرَجٍ من هذا
الدليل** — لا في أمرٍ ولا في سجلٍّ ولا في نسخةٍ من شاشة.

## ١) بوّابةُ الإطلاق — تُشغَّل قبل كلِّ نشر

```bash
php artisan hub:ai-release-check            # جدولٌ يُقرَأ
php artisan hub:ai-release-check --json     # للآلةِ وللأرشفة
php artisan hub:ai-release-check --strict   # التحفّظُ يُسقِط أيضاً
```

**قراءةٌ فقط:** لا تكتب صفّاً ولا إعداداً، ولا تُنادي مزوّداً، **ولا تُنفق
ديناراً**. تقرأ الإعداداتِ وصفوفَ القاعدةِ والمخطَّطَ وملفّاتِ المستودع.

| الحكم | رمزُ الخروج | ماذا تفعل |
|---|---|---|
| `RELEASE GATE PASS` | `0` | امضِ |
| `RELEASE GATE PASS WITH WARNINGS` | `0` (و`1` مع `--strict`) | **اقرأ كلَّ تحفّظٍ وقرِّر** |
| `RELEASE GATE BLOCKED` | `1` | لا نشر |

**والتحفّظُ ليس نجاحاً.** عدُّه نجاحاً بصمتٍ يُفرغ الدرجةَ الوسطى من معناها،
وهي أهمُّ الثلاث: تقول «هنا ما لا يعرفه الفحصُ وحدَه».

> **ولا تُوضَع هذه البوّابةُ في CI.** مستودعٌ بلا مزوّدٍ ولا نموذجٍ مُهيَّأٍ
> يُعيد `BLOCKED` بحقّ — فوضعُها في CI يجعلها حمراءَ دائماً فتُعطَّل بعد
> أسبوع. موضعُها **الخادمُ قبل النشرِ وبعدَه**.

### الفحوصُ ومعانيها

| المعرّف | يسأل | إخفاقُه يعني |
|---|---|---|
| `SCHEMA_TABLES` | أجداولُ الذكاءِ الثمانيةُ موجودة؟ | ترحيلاتٌ معلّقة |
| `SCHEMA_TELEMETRY` | أأعمدةُ تشخيصِ الدورةِ الأربعةُ موجودة؟ | **لا يُشخَّص إخفاقٌ إلّا بالتخمين** |
| `GATEWAY_CONFIGURED` | أالبوّابةُ مضبوطةٌ ومُفعَّلة؟ | لا طلبَ يخرج |
| `GATEWAY_LOOPBACK` | أهي على حلقةٍ محلّيّة؟ | **بوّابةٌ تحمل مفاتيحَ المزوّدين قد تكون مكشوفة** |
| `GATEWAY_PROBED` | أفُحص الاتصالُ والتوليدُ على البصمةِ الحاليّة؟ | جاهزيّةٌ مُدّعاةٌ لا مُثبَتة |
| `PROVIDER_CREDENTIAL` | أثمّة اعتمادٌ **متحقَّقٌ منه**؟ | الإدخالُ ليس قبولاً |
| `MODELS_REGISTERED` | أثمّة نموذجٌ مُفعَّلٌ وقابلٌ للتوجيه؟ | لا وجهةَ لطلب |
| `ASK_PROFILE_CHAIN` | أسلسلةُ غرضِ المساعدِ غيرُ فارغة؟ | طلبٌ بلا سلسلةٍ لا يُوجَّه |
| `ASK_SUITABILITY` | أفي السلسلةِ نموذجٌ يدعم `chat + tools`؟ | **سلسلةٌ مملوءةٌ لا تُجيب سؤالاً** |
| `ASK_FALLBACK_DEPTH` | أللسلسلةِ تكرارٌ حقيقيٌّ عبر مزوّدين؟ | تهدئةُ مزوّدٍ تُسقطها كلَّها معاً |
| `WRITE_TOOLS_CLOSED` | أ`WRITE_TOOLS` ما زالت فارغة؟ | النموذجُ صار يكتب |
| `FAILURE_CODES_LIVE` | أكلُّ رمزٍ له رسالة؟ | رمزٌ أخرسُ في وجهِ المستخدم |
| `LEDGER_NO_CONTENT` | أخلا الدفترُ من أعمدةِ محتوًى؟ | **تسريبٌ عبر سجلٍّ يُقرَأ بصلاحيّةٍ أخرى** |
| `LEDGER_STALE_HOLDS` | أثمّة حجوزٌ معلّقةٌ فوق عمرِها؟ | ميزانيّةٌ تُخنَق بمالٍ لم يُنفَق |
| `COST_UNKNOWN_NOT_ZERO` | أثمّة رقمُ كلفةٍ بمصدرٍ مجهول؟ | رقمٌ بلا مصدرٍ لا يُجمَع |
| `BACKUP_COVERAGE` | أجداولُ الذكاءِ في النسخة؟ | **استعادةٌ تُعيد Hub بلا ذكاء** |
| `OPENAPI_FRESH` · `VERSION_SYNC` | أالمواصفةُ والنسخةُ متطابقتان؟ | وثيقةٌ تصف حالةً انقضت |
| `DOCS_PRESENT` | أوثائقُ الإطلاقِ الخمسُ موجودة؟ | تشغيلٌ بلا دليل |

> والتقريرُ النهائيُّ للمرحلةِ في `45-phase5-final-report.md`.

## ٢) النشر — أربعُ مراحل

### ② أ — قبل النشر (على الخادم)

```bash
php artisan hub:backup --verify          # نسخةٌ تُقرَأ لا نسخةٌ تُكتَب فقط
php artisan hub:ai-release-check --json > /tmp/gate-before.json
git rev-parse HEAD                        # **اكتب هذا الرقمَ** — هو نقطةُ تراجعِك
php artisan migrate:status | grep -i pending
```

**والنسخةُ أوّلاً بترتيبِها:** البوّابةُ (قاعدةُ LiteLLM) ثمّ Hub. والعكسُ
يُنتج توجيهاً يشير إلى نماذجَ لم تُنسَخ.

### ② ب — النشر

من **Git Version Control** في Hub (أو `git fetch && git checkout <sha>`):

```bash
composer install --no-dev --optimize-autoloader   # إن تغيّر composer.lock
php artisan migrate --force                        # الهجراتُ كلُّها إضافيّة
php artisan optimize:clear
php artisan config:cache && php artisan route:cache && php artisan view:cache
```

**ولا `git clean` ولا `reset --hard`.** فملفّاتٌ غيرُ متعقَّبةٍ مشروعةٌ على
الخادم: `error_log` · `public/storage` (وصلةٌ رمزيّة) · `.env`.

### ② ج — بعد النشر

```bash
php artisan hub:schema-check                  # ما يقرؤه الكودُ ولا تملكه القاعدة
php artisan hub:ai-release-check              # قارِنه بـ/tmp/gate-before.json
curl -sf 'http://127.0.0.1/healthz?probe=ready'
php artisan hub:ai-reconcile                  # معاينةٌ — ثمّ --apply إن لزم
```

ثمّ **من الواجهة** (لا من الطرفيّة): مركزُ الذكاء ← البوّابة ← فحصُ الاتصال ·
النماذج ← اختبارُ توليد · «اسأل Hub» ← سؤالٌ واحدٌ حقيقيّ.

### ② د — التراجع

```bash
git checkout <sha-السابق>                      # الرقمُ المكتوبُ في ② أ
composer install --no-dev --optimize-autoloader
php artisan optimize:clear && php artisan config:cache
```

**ولا `migrate:rollback`.** هجراتُ هذه المنصّةِ **إضافيّةٌ غيرُ مدمّرة**:
عمودٌ زائدٌ لا يكسر كوداً أقدمَ لا يعرفه، **وإسقاطُه يمحو بياناتِ إنتاج**.
فالتراجعُ تراجعُ شيفرةٍ لا تراجعُ مخطَّط.

**وإن لزم تراجعُ بيانات** (حالةٌ نادرةٌ جدّاً): استعادةٌ من نسخةِ ② أ على
**قاعدةٍ معزولةٍ أوّلاً**، ثمّ قرارُ المالكِ صراحةً. لا استعادةَ على الإنتاج
بلا نسخةٍ أحدثَ منها.

## ٣) اليومُ العاديّ — أين يُقرَأ ماذا

| السؤال | الوجهة |
|---|---|
| أالبوّابةُ حيّة؟ | مركزُ الذكاء ← البوّابة |
| أيُّ مزوّدٍ معتمَدٌ ومتحقَّقٌ منه؟ | مركزُ الذكاء ← المزوّدون |
| أيُّ نموذجٍ مسجَّلٌ وبأيِّ قدرات؟ | مركزُ الذكاء ← النماذج |
| **لماذا هذا النموذجُ يصلح للمساعدِ أو لا؟** | مركزُ الذكاء ← التوجيه (وسمُ الملاءمة) |
| كم أنفقنا وعلى ماذا؟ | مركزُ الذكاء ← الاستهلاك |
| **لماذا أخفق طلبٌ بعينِه؟** | مركزُ الذكاء ← الاستهلاك ← «آخرُ الدورات» |
| ما حالةُ المسارِ كلِّه؟ | مركزُ الذكاء ← التشخيص |

### قراءةُ «آخرِ الدورات»

كلُّ صفٍّ **محاولةٌ واحدة** لا طلبٌ منطقيّ. والأعمدةُ تُقرأ هكذا:

- `relation` — `initial` أوّلُ محاولة · `retry` إعادةٌ على النموذجِ نفسِه ·
  `fallback` قفزةٌ إلى نموذجٍ آخر.
- `finish_reason` — **أوّلُ ما يُسأل عنه عند كلِّ إخفاق**. و`length` تعني
  السقفَ نفد.
- `reasoning_tokens` مقابل `max_output_tokens` — **إن تقاربا فالنموذجُ أنفق
  سقفَه تفكيراً قبل أن يُجيب**، وذاك سببُ `MODEL_REASONED_ONLY`.
- `tool_requested` — أداةٌ من مفرداتٍ مغلقةٍ خمس. وفراغُه في كلِّ الصفوفِ
  يعني **نموذجاً لا يُصدر طلباتِ أدوات**.

## ٤) أعطالٌ متكرّرةٌ وعلاجُها

### ٤٫١ «لا توجد بيانات» والبياناتُ موجودة

**التشخيص:** اقرأ صفَّ الدورةِ في «آخرُ الدورات».

| ما تراه | السبب | العلاج |
|---|---|---|
| `tool_requested` فارغٌ في كلِّ الصفوف | النموذجُ لا يُصدر طلباتِ أدوات | مركزُ الذكاء ← التوجيه: وسمُ «غيرُ مُلائم» يُسمّي القدرةَ الناقصة |
| `finish_reason = length` و`reasoning_tokens` ≈ السقف | السقفُ أُنفق تفكيراً | ارفع `ask.max_output_tokens` أو اختر نموذجاً غيرَ مفكّرٍ للمساعد |
| رمزُ `NO_SERVER_READ` | النموذجُ أجاب بلا قراءةٍ واحدة | لا يُعرَض جوابٌ مُختلَق — راجع ملاءمةَ النموذج |
| مصادرُ = ٠ ولا رمزَ إخفاق | **عطلٌ يُبلَّغ** — لم يعد ممكناً بعد v2.584.0 | افتح بلاغاً بمعرّفِ الطلب |

### ٤٫٢ النماذجُ اختفت من الكتالوجِ بعد حذفِ نموذج

**لا شيءَ انكسر.** الكتالوجُ يُقرَأ من البوّابةِ ولا يعتمد على نموذجٍ مسجَّل
(مُثبَتٌ في `AiModelDeletionRecoveryTest`). اضغط **تحديث/اكتشاف** في مركزِ
الذكاء ← النماذج ← تصفّحُ الكتالوج.

**وحذفُ النموذجِ لا يحذف اعتمادَ المزوّدِ ولا يُبطله** — الاعتمادُ يبقى
صالحاً لتبنّي نموذجٍ آخر.

### ٤٫٣ كلُّ طلبٍ يفشل فجأةً بعد استعادة

**السببُ الأرجح:** قاعدةُ البوّابةِ استُعيدت بملحٍ مختلف. صفوفُ الاعتمادِ
**حاضرةٌ ولا تُفَكّ** — والنماذجُ تظهر وكلُّ نداءٍ يفشل، فيُشخَّص «عطلَ
شبكة». اقرأ `docs/ai-hub/43-disaster-recovery.md` § ٣.

### ٤٫٤ الميزانيّةُ مخنوقةٌ ولا إنفاقَ يُرى

حجوزٌ معلّقةٌ من مساراتٍ ماتت بين الحجزِ والالتزام. يكشفها
`LEDGER_STALE_HOLDS` في بوّابةِ الإطلاق، ويُفرج عنها المِقصُّ الدوريّ —
**فتأكّد أنّ المجدوِل يعمل** (`docs/RUNBOOKS.md` §1).

## ٥) ما يُصعَّد إلى المالكِ ولا يُقرَّر هنا

- إدخالُ أو تدويرُ **أيِّ اعتمادِ مزوّد** — يُدخَل من داخلِ مركزِ الذكاءِ
  وحدَه، ومن المالكِ وحدَه.
- تغييرُ **`LITELLM_SALT_KEY`** أو **`APP_KEY`** — قرارٌ محسومٌ بالمنع.
- **توسيعُ `WRITE_TOOLS`** — قرارُ مالكٍ لا تفصيلُ تنفيذ.
- أيُّ **توليدٍ مدفوعٍ** لأغراضِ التشخيص.
- استعادةٌ على قاعدةِ الإنتاج.
