## ٣) متطلّباتُ الوكيلِ كما تقولها وثائقُ هذا الإصدار — لا كما افترضت المرحلةُ ١

| المتطلَّب | ما تقوله الوثائق |
|---|---|
| `LITELLM_MASTER_KEY` | «the proxy admin credential: it authenticates admin API calls and is the Admin UI login password» · **يبدأ بـ`sk-`** |
| `DATABASE_URL` | لازمٌ لـ«the proxy's auth and tracking features» — والوكيلُ **يقلع بدونه** كبوّابةٍ عديمةِ الحالة تقرأ `config.yaml` وحدَه |
| `LITELLM_SALT_KEY` | «encrypts provider credentials stored in the DB. **Set once, never change it**» |
| **قيدٌ لا رجعةَ فيه** | «`DATABASE_URL` **cannot be rotated after you add models**: it encrypts the provider credentials stored in your database» |
| المنفذُ الافتراضيّ | **4000** |
| فحصُ الصحّة | `/health/liveliness` و`/health/readiness` — **بلا مصادقة**؛ و`/health/readiness` يكشف حالةَ القاعدة. والتفصيلُ الكاملُ على `/health/readiness/details` **بمصادقة** |

### وهذا يغيّر نطاقَ المرحلة ١٫٥ — بدليل

افترضت المرحلةُ ١ أنّ القاعدةَ **شأنُ المرحلة ٢**. ووثائقُ الإصدار تقول غيرَ
ذلك: `SALT_KEY` **يُضبَط مرّةً ولا يُغيَّر**، و`DATABASE_URL` **لا يُدوَّر بعد
إضافةِ النماذج**. فتأجيلُهما يعني أنّ تركيبَهما لاحقاً **ليس إضافةً بل هجرةٌ
مدمّرة** لاعتماداتٍ مشفّرةٍ بمفتاحٍ آخر.

**فالقرار:** تُجهَّز **القاعدةُ ومفتاحُ الملح في المرحلة ١٫٥**، ولو لم تُستعمل
إلّا في المرحلة ٢. تجهيزٌ لا استعمال — وهو أرخصُ من هجرةٍ لا رجعةَ فيها.

## ٤) الأمرُ الذي تشغّله على الخادم — **الآن**

```bash
cd ~/path/to/lynomia-hub && git fetch origin && \
git checkout claude/lynomia-hub-enterprise-upgrade-xn4p2t && git pull && \
bash deploy/litellm/preflight.sh 2>&1 | tee /tmp/litellm-preflight.txt
```

ثمّ الصق **كلَّ** مخرجاتِ `/tmp/litellm-preflight.txt`.

- **قراءةٌ فقط**: لا يثبّت، ولا يغيّر إعداداً، ولا يفتح منفذاً.
- إن تعذّر `git`، انسخ الملفَّ وحدَه وشغّله: `bash preflight.sh`.
- شغّله بـ`sudo` إن طلب: بعضُ الفحوص (وحداتُ systemd، عفريتُ Docker) تُخفى عن
  مستخدمٍ عاديّ فيُقرأ الغيابُ «غيرَ متاح» وهو متاح.

**ولا يُختار وضعُ التشغيلِ قبل قراءةِ مخرجاتِه.** الخياران المُعدَّان:

| الوضع | يُختار حين | لماذا |
|---|---|---|
| **systemd + venv** | `systemd` نشطٌ و`root/sudo` متاحٌ وDocker غائبٌ أو متعذّر | **الأرجحُ على خادمِ cPanel** — cPanel لا تدعم رسميّاً Docker على خادمِها |
| **Docker compose** | عفريتُ Docker يعمل ويُوصَل إليه | عزلٌ أنظف وترقيةٌ أبسط — إن كان مدعوماً على خادمِك |
| **لا شيء** | لا `root` ولا `systemd` | لا بوّابةَ على هذا الخادم — تُراجَع الخيارات |

## ٥) التصميمُ الداخليّ — البوّابةُ لا تُكشَف

```
المتصفّح ──HTTPS──► Hub (PHP)  ──► 127.0.0.1:4000 ──► LiteLLM ──HTTPS──► المزوّدون
                                    ▲
                        لا منفذَ عامٌّ · لا نطاقٌ فرعيّ · لا reverse proxy
```

- الربطُ `--host 127.0.0.1 --port 4000` (أو `-p 127.0.0.1:4000:4000` في compose).
- **لا قاعدةَ جدارٍ ناريٍّ تُفتَح**، ولا سجلَّ DNS.
- **والمفتاحُ حاجزٌ ثانٍ لا زينة**: `127.0.0.1` يمنع الإنترنتَ ولا يمنع جيرانَ
  الخادم — وعلى خادمِ cPanel حساباتٌ عدّة، وأيُّ سكربتٍ عليها يطلب المنفذ.
- وPostgres كذلك على `127.0.0.1:5432` لا غير.

## ٦) دورةُ الحياة — الأوامرُ المقصودة

تُكتب نهائيّاً بعد اختيارِ الوضع؛ وهذه عقودُها:

| الفعل | systemd + venv | Docker compose |
|---|---|---|
| install | `deploy/litellm/install-systemd.sh` (يُكتب بعد الفحص) | `docker compose up -d` |
| start / stop / restart | `systemctl start\|stop\|restart litellm` | `docker compose start\|stop\|restart` |
| status | `systemctl status litellm` | `docker compose ps` |
| logs | `journalctl -u litellm -f` | `docker compose logs -f` |
| health | `curl -fsS http://127.0.0.1:4000/health/liveliness` | نفسُه |
| upgrade | تثبيتُ رقمٍ جديدٍ في venv ثمّ `restart` | تعديلُ الوسم ثمّ `up -d` |
| **rollback** | إعادةُ التثبيتِ على **`1.100.1`** ثمّ `restart` | إعادةُ الوسمِ إلى `1.100.1` ثمّ `up -d` |
| backup | `pg_dump` لقاعدةِ البوّابة + نسخةُ `config.yaml` | نفسُه |

## ٧) الأسرارُ — لا واحدَ منها في Git

| السرّ | أين يعيش | كيف يصل |
|---|---|---|
| `LITELLM_MASTER_KEY` | ملفُّ بيئةٍ على الخادمِ بصلاحيّة `0600` **خارج** شجرةِ المستودع | يقرؤه محرّكُ الخدمة (`EnvironmentFile` أو `env_file`) |
| `LITELLM_SALT_KEY` | المكانُ نفسُه — **ويُنسَخ احتياطيّاً فوراً** | نفسُه |
| `DATABASE_URL` | المكانُ نفسُه | نفسُه |
| نسخةُ Hub من مفتاحِ الإدارة | `settings.ai.gateway_key` **مشفّرةً** (`enc:`) | تُدخَل مرّةً من المركزِ خلفَ تأكيدِ هويّة |

- **يُضاف `deploy/litellm/*.env` إلى `.gitignore`**، ويُسلَّم **مثالٌ** بلا قيم.
- **مفتاحُ الملحِ يُنسَخ احتياطيّاً يومَ إنشائِه**: فقدُه = فقدُ كلِّ اعتمادِ
  مزوّدٍ مخزَّنٍ في القاعدة، **بلا استرجاع**.
- وHub **لا يعيد المفتاحَ إلى المتصفّح** أبداً — قناعٌ فقط (محروسٌ باختبار).

## ٨) ترتيبُ الإثباتِ بعد التنصيب — ثلاثُ درجاتٍ لا تُخلَط

1. **من الخادمِ نفسِه:** `curl -fsS http://127.0.0.1:4000/health/liveliness`
   ثمّ `/health/readiness` (يكشف حالةَ القاعدة) — **بلا مصادقة**.
2. **بالمفتاح:** `curl -H "Authorization: Bearer $KEY" http://127.0.0.1:4000/v1/models`
   — يثبت أنّ المفتاحَ مقبول.
3. **من Hub:** زرُّ «اختبار الاتصال» حتّى **`up === true`**، فتُختَم البصمةُ
   وتصير حالةُ القدرة `READY`.

**ونجاحُ البوّابةِ يبقى منفصلاً عن نجاحِ التوليد**: لا يُربَط مزوّدٌ في هذه
المرحلة، و`ai.generation_ok` تبقى `false` — والمركزُ يقولها صراحة.
