# ٢٨) عقدُ تسجيلِ النموذج — `POST /model/new`

> **مقيسٌ بتحميلِ نماذجِ جسمِ `litellm==1.101.0` المثبّتةِ وسؤالِها**، لا مقروءٌ
> من ذاكرةٍ ولا مُجرَّبٌ على بوّابةٍ حيّة. واللقطةُ في
> `tests/Fixtures/ai/litellm-1.101.0-write-contract.json` مولَّدةٌ من القياسِ نفسِه.

---

## ١) العطل — كما وقع في القبولِ الحقيقيّ

**مركزُ الذكاء ← المزوّدون ← النماذج ← تسجيلُ نموذج**، فعاد:

```
HTTP 422
{"detail":[{"type":"model_type","loc":["body","model_info"],
 "msg":"Input should be a valid dictionary or instance of ModelInfo",
 "input":[],"ctx":{"class_name":"ModelInfo"}}]}
```

`"input":[]` يقول كلَّ شيء: Hub أرسل `model_info` **مصفوفةً** والعقدُ يطلب **كائناً**.

---

## ٢) السبب — لغةٌ لا بوّابة

في PHP لا فرقَ بين «قائمةٍ فارغة» و«خريطةٍ فارغة»: كلتاهما `[]`. وفي JSON الفرقُ
حاسم: `[]` مصفوفةٌ و`{}` كائن.

```php
// قبل — app/Support/Ai/Gateway/LiteLlmAdmin.php::createModel()
'model_info' => $modelInfo,       // $modelInfo = []  ⇒  "model_info":[]
```

**ولم يكن الحقلُ وحيداً.** قياسُ نماذجِ الجسمِ أثبت أنّ **ثلاثَ حمولاتٍ** تحمل
الخللَ نفسَه، ونجَت اثنتان منها في الإنتاج **بالمصادفة** لا بالتصميم — لأنّ
مُستدعيَهما يمرّران وصفاً غيرَ فارغ:

| المسار | الحقل | الحكمُ المقيسُ بالشكلِ القديم |
|---|---|---|
| `POST /model/new` | `model_info` | `REJECTED: model_type` ← **هذا ما وقع** |
| `POST /credentials` | `credential_info` | `REJECTED: dict_type` |
| `PATCH /credentials/{name}` | `credential_info` | `REJECTED: dict_type` |

---

## ٣) العقدُ المقيس

### ٣٫١ `Deployment` — جسمُ `POST /model/new`

| الحقل | إلزاميّ | النوع | ملاحظة |
|---|---|---|---|
| `model_name` | ✅ | نصّ | الاسمُ في Hub |
| `litellm_params` | ✅ | **كائن** | `[]` ⇒ `model_type` |
| `litellm_params.model` | ✅ | نصّ | **الحقلُ الإلزاميُّ الوحيدُ داخلَه** |
| `litellm_params.*` | — | `extra=allow` | ومنها `litellm_credential_name` |
| `model_info` | — | **كائن** أو `null` أو محذوف | `[]` ⇒ `model_type` · `{}` مقبول |

وأحكامٌ أخرى مقيسة: `model_info.tier` من `free`/`paid` وحدَهما، ومفتاحٌ زائدٌ
في أيِّ مستوًى **يُقبَل** (`extra=allow`)، و`model_info` المحذوفُ يُولَّد له
معرّفٌ تلقائيّاً.

### ٣٫٢ الاعتماد

| الجسم | إلزاميّ | النوع |
|---|---|---|
| `credential_name` | ✅ | نصّ |
| `credential_info` | ✅ | **كائن** (`dict`) |
| `credential_values` | ✅ عند التحديث | **كائن** |

---

## ٤) الحمولة — قبل وبعد (بلا أسرار)

**قبل** — مرفوضةٌ بـ٤٢٢:

```json
{"model_name":"hub-general",
 "litellm_params":{"model":"مزوّد/نموذج","litellm_credential_name":"hub-x-abc"},
 "model_info":[]}
```

**بعد** — مقبولةٌ، وقد تحقّق قبولُها بتمريرِ الحمولةِ الفعليّةِ الخارجةِ من PHP
على نموذجِ الجسمِ نفسِه:

```json
{"model_name":"hub-general",
 "litellm_params":{"model":"مزوّد/نموذج","litellm_credential_name":"hub-x-abc"},
 "model_info":{}}
```

**ولا مفتاحَ مزوّدٍ في أيٍّ منهما** — المرجعُ وحدَه يعبر، كما هو تصميمُ W3.

---

## ٥) الإصلاح — في طبقةِ النقلِ لا في حقلٍ بعينِه

```php
/** خريطةٌ حرّةٌ تخرج كائناً — ولو كانت فارغة */
private static function obj(array $map): \stdClass
{
    return (object) $map;
}
```

يمرّ بها **كلُّ** حقلٍ يُعلنه العقدُ كائناً: `litellm_params` · `model_info` ·
`credential_values` · `credential_info` — في التسجيلِ والاعتمادِ والتدويرِ وفحصِ
الاتّصال. وهي **محايدةٌ للمزوّدِ تماماً**: لا تعرف مزوّداً ولا حقلاً بعينِه.

**وأُضيف مع الإصلاح** تفسيرٌ عربيٌّ لرمزِ ٤٢٢ — كان يعود للمدير رمزاً عارياً
يُخلَط بـ٤٠٠. والفرقُ عمليّ: ٤٠٠ تعني «لم يُفهَم الطلب»، و٤٢٢ تعني «فُهم ورُفض
**حقلٌ بنوعِه**» — فيُبحَث في الأنواعِ لا في المسار.

---

## ٦) الحارسُ الدائم

`tests/Feature/AiHub/LiteLlmWritePayloadContractTest.php` — عشرةُ اختبارات:

- كلُّ كاتبٍ في العميلِ يُشغَّل، ويُفحَص **متنُه الخامّ** حقلاً حقلاً بالحقولِ
  الكائنيّةِ المقيسة. **ولا كاتبَ خارجَ المسح**: الاختبارُ يقارن مفاتيحَ
  المُشغِّلات بمفاتيحِ اللقطةِ فيسقط إن ظهر مسارُ كتابةٍ بلا حارس.
- الحقولُ الإلزاميّةُ حاضرةٌ في كلِّ حمولة.
- اللقطةُ تشهد على نفسِها: الإصدارُ، وأنّ الشكلَ القديمَ مرفوضٌ والجديدَ مقبول.

**والتأكيدُ على المتنِ الخامِّ لا على `data()`** — الأخيرةُ تُعيد ما بُنيَ لا ما
يُرسَل، وهي المصيدةُ التي أخفت العطلَ أوّلَ مرّة.
