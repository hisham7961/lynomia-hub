# تصميمُ الدفعةِ الثانية — **الحارسُ يفشل مغلقاً**

> يعالج `F-16` (الجذر · ١٠٩ مواضع) و`F-04` (العَرَض · ٨ وحدات).
> كُتب أثناء انتظارِ بوّابةِ المحرّكين لدفعةِ v2.541.0.

## المشكلةُ في سطر

```php
if (($cids = hub_company_ids($user)) !== null && ($ccol = hub_company_col($module))) {
    …يُطبَّق العزل…
}
```

الشرطُ الثاني يجعل **غيابَ العمودِ إذناً بالمرور**. فثماني وحداتٍ بلا عمودِ شركةٍ
تُقرأ كاملةً لمستخدمٍ معزول — والحادثةُ تحمل اسمَ المشروعِ والعميلِ والسببَ الجذريّ.

## لماذا لا يكفي `1 = 0`

الحلُّ الذي اقترحه المتحدّي — أن يُرجع الحارسُ `1=0` عند غيابِ العمود — **يُغلق
الثغرةَ ويكسر المنتج**: المستخدمُ المعزولُ يصير لا يرى **أيَّ** حادثةٍ أو طلبٍ
داخليٍّ أو فكرة، وهي وحداتُ عملٍ يوميّة. الأمانُ الذي يُفرغ الشاشةَ ليس أماناً بل
تعطيل، وقاعدةُ المراجعة: **لا تُحذف قدرةٌ صالحة**.

## التصميمُ المعتمَد — ثلاثةُ أبوابٍ مُعلَنة، ورابعٌ مغلق

الانتماءُ يُعلَن في سجلِّ الوحدات، ولا يُترَك للاستنتاج:

| الحالة | السلوك |
|---|---|
| ① للوحدةِ **عمودُ شركة** | كما هي اليوم (`whereIn(company_id, $cids)`) |
| ② للوحدةِ **مسارُ انتماءٍ مُعلَن** (`company_via`) | `whereIn($col, subquery)` على جدولِ الأبِ بشركاتِ القارئ |
| ③ الوحدةُ **مُعلَنةٌ صراحةً بلا انتماء** مع سببٍ مكتوب | تُترَك للمصفوفة (قرارٌ موثَّق) |
| ④ **لم تُعلِن شيئاً** | **`whereRaw('1 = 0')`** — يفشل مغلقاً |

**والمكسبُ الحقيقيُّ في ④**: اليومَ الصمتُ يعني «افتح»؛ وبعدها الصمتُ يعني «أغلق»
**ويسقط اختبارٌ يطالب بالإعلان**. فالبابُ الحادي والعشرون لا يُولَد صامتاً.

## مساراتُ الانتماءِ المقيسة (لا المفترَضة)

| الوحدة | الجدول | المسار |
|---|---|---|
| `incidents` | `incidents` | `project_id` ← `projects.company_id` |
| `requests` | `internal_requests` | `project_id` ← `projects.company_id` |
| `ideas` | `ideas` | `project_id` ← `projects.company_id` |
| `deps` | `dependencies` | `project_id` ← `projects.company_id` |
| `deploys` | `deployments` | `project_id` ← `projects.company_id` |
| `competitors` | `competitors` | `service_id` ← `services.company_id` |
| `plans` | `pricing_plans` | `service_id` ← `services.company_id` |
| `restores` | `restore_tests` | **لا أبَ لها** — `created_by` وحده ⇒ قرارُ مالكٍ: إمّا الصنف ③ بسببٍ مكتوب، أو عمودُ شركةٍ إضافيّ |

## الأبُ الفارغ (`project_id IS NULL`)

حادثةٌ بلا مشروع: من يملكها؟ **يُحتذى بما يفعله النظامُ للعمود** — `hub_company_null_is_unowned`
يقرّر لكلِّ وحدةٍ أيُقرأ الفراغُ «للجميع» أم «لا لأحد». يُطبَّق المبدأُ نفسُه على
المسار، **ولا يُخترَع سلوكٌ ثالث**.

## الحارسُ الذي يُثبت الإصلاح

اختبارٌ يمرّ على **الـ٨٥ وحدةً**: لكلٍّ منها عمودٌ، أو مسارٌ مُعلَن، أو إعلانُ
«بلا انتماء» بسبب. **يسقط اليومَ في ثمانٍ — وهو معيارُ النجاحِ بعينه.**

وثانٍ سلوكيّ: مستخدمٌ معزولٌ بشركةٍ «أ» لا يقرأ سجلاً مرتبطاً بمشروعٍ لشركةِ «ب»
في **كلِّ** وحدةٍ من الثماني، عبر الويبِ و`/api/v1` والجوّالِ والمزامنة.

## ما لا يفعله هذا التصميم

لا يمسّ الـ١٠٩ موضعاً الأخرى دفعةً واحدة. `hub_scope` أهمُّها وأكثرُها أثراً،
وإغلاقُه يُثبت النمطَ قبل تعميمه. والبقيّةُ تُجرَد وتُصنَّف في دفعةٍ تالية —
**لأنّ إصلاحاً واحداً مُثبَتاً خيرٌ من مئةٍ غيرِ مُختبَرة.**
