## المبادئُ الحاكمة (من توجيه الطور)

1. **الكودُ هو المرجع.** لا يُوثَق بتقاريرَ نهائيّةٍ سابقةٍ إن خالفها الكود. كلُّ ادّعاءٍ في
   هذه الوثائق مسنودٌ إلى ملفٍ وسطرٍ أو إلى اختبارٍ يمرّ.
2. **لا تضخُّمَ ميزات.** لا تُبنى ميزةٌ جديدةٌ في هذا الطور؛ تُصلَح العيوبُ الحقيقيّةُ فقط،
   بأصغرِ طبقةٍ صحيحة.
3. **إثباتٌ لا ادّعاء.** كلُّ عيبٍ حقيقيّ: إعادةُ إنتاج → اختبارٌ يفشل أولاً → إصلاح →
   اختبارٌ مُوَجَّه → انحدارُ النطاق.
4. **الإضافةُ لا الكسر.** لا حذفَ مسار، ولا تغييرَ عقدِ API، ولا هجرةً مُدمِّرة.
5. **المحرّكان إلزاميّان.** لا قرارَ «جاهز» إن سقطت حزمةُ SQLite أو حزمةُ MySQL/MariaDB.
6. **القرارُ واحد.** `FINAL_REPORT.md` ينتهي بقرارٍ واحدٍ صادقٍ لا غير.

## مجالاتُ التدقيق (§3 من التوجيه)

- عزلُ الشركات والعملاء (cross-company / client-internal)
- صلاحيّةُ API و IDOR على `/api/v1` و `/api/mobile/v1`
- XSS / SQLi / SSRF / تسريبُ الأسرار / إعادةُ التوجيه المفتوحة
- افتراضاتُ الحذفِ الناعم والمخطّط (`deleted_at` — §64 صراحةً)
- الأداء / N+1 / القوائمُ غيرُ المحدودة / اجتيازُ الرسم
- صدقُ سجلِّ القدرات (Feature Registry)
- ازدواجُ المحرّكات المعماريّ
- تغطيةُ النسخ الاحتياطيّ، الهجرات، تهيئةُ الإنتاج، المجدول، الطابور
