# 04 — التنقّلُ والاكتشاف

## المصدرُ الواحد للمعمارِ المعلوماتيّ

`config/hub_ia.php` + `App\Support\InformationArchitecture` — سطحان، تسعةُ مجالات، أقسامٌ لكلِّ
وحدة/مركز. الرؤيةُ تُفوَّض إلى بوّابةِ كلِّ وجهةٍ الحقيقيّة (لا تعدادُ جمهورٍ ثابت). الشريطُ الجانبيّ،
فتاتُ الخبز، خريطةُ النظام (`/system-map`)، ولوحةُ الأوامر — كلُّها فوق هذا المصدر الواحد.

## أيتامُ الواجهة (orphans)

فحصُ تغطيةِ المسارات (`RouteCoverageTest`/`DiscoverabilityAuditTest`) مقابلَ وجهاتِ IA:

| النوع | العدد | ملاحظة |
|---|---|---|
| أيتامُ الواجهةِ الأساسيّة | 0 | كلُّ وجهةٍ أساسيّةٍ في IA |
| أيتامُ واجهةِ الإدارة | 0 | |
| أيتامٌ سياقيّة | 0 | |
| روابطُ تنقّلٍ ميّتة | 0 | |

**مساران مبنيّان-غيرُ-مربوطين (P3، غيرُ حاجزَين):** `security.event` (صفحةُ حدثٍ أمنيٍّ مفردة)
و`dm.edit` (تحريرُ رسالةٍ مباشرة) — مبنيّان ويعملان لكنْ بلا رابطِ تنقّلٍ مباشرٍ من الشريط.
مصنّفان `P3` (اكتشافٌ لا فقدُ ميزة)، مُوثَّقان في `FINDINGS.md`.

## البحثُ ونتائجُه المُنطَّقة

- مزوّدو البحث يمرّون بنفسِ بوّاباتِ الرؤية؛ **نتائجُ بحثٍ غيرُ مُصرَّحة = 0**
  (`SearchDestinationsTest`, `SearchDmLeakTest`, `WorkOsGlobalSearchTest`).
- العميلُ لا تظهر له وجهاتٌ داخليّة في البحث أو لوحةِ الأوامر.

## مركزُ التواصلِ في التنقّل

مركزُ التواصل مربوطٌ في الشريط الرئيس عبر IA (`hub_top_links`)، ومنتقي المشاركين قابلٌ
للاستعمال (غيرُ مُحدَّدٍ افتراضاً). داخليٌّ حصراً (`abort_if(hub_is_client)`).

## الكيان 360 — الاكتشافُ المتبادل

صفحاتُ الموظف/المحطة/الأصل/المشروع 360 تتقاطع فيما بينها (روابطُ المحطة↔الأصل↔المشروع↔الموظف)
وتربط برسمِ العلاقات، ضمنَ بوّاباتِ الرؤية.

**خلاصة:** الأيتامُ الحاجزة = 0؛ البندان P3 مُوثَّقان لا حاجزَين.
