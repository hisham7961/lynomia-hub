## AUDIT-1 — عزلُ العميل على `/api/v1`

- **الشدّة:** P1 (أُصلِح)
- **المجال:** الأمن / عزلُ العميل / صلاحيّةُ API
- **الوصف:** مسارات `/api/v1` تعمل تحت `ApiAuth` لا `PortalGuard`، فحسابُ عميلٍ برمزِ API ودورٍ
  واسعٍ يكشف **وجودَ** وحداتٍ داخليّةٍ خارجَ قائمتِه (200 بدل 404).
- **الدليل:** `routes/api.php` (`/api/v1` تحت `ApiAuth`)؛ `V1Controller::resolveApi()` لم يكن
  يستشير قائمةَ العميل.
- **الأثر:** كشفُ وجودِ وحدةٍ داخليّةٍ لحسابِ عميل (العزلُ الصفّيُّ يمنع قراءةَ بياناتِ شركةٍ
  أخرى، لكنّ الكشفَ عن وجودِ الوحدةِ خرقٌ للعزل).
- **الجذر:** غيابُ حاجزِ نوعِ الحساب على سطحِ `/api/v1` (كان على البوّابةِ الويب/الجوّال فقط).
- **الإصلاح:** حاجزٌ صريحٌ في `V1Controller::resolveApi()` يعيد 404 لأيِّ وحدةٍ خارجَ
  `PortalGuard::MODULE_ALLOW` لحساباتِ العميل؛ رُفِعت `MODULE_ALLOW` إلى `public const` (مصدرٌ واحد).
- **اختبارُ الانحدار:** `FinalAuditHardeningTest::test_client_api_token_is_confined_to_allowed_modules`
  + `test_internal_api_token_still_reaches_modules`.
- **الحالة:** ✅ FIXED

## AUDIT-7 — N+1 محدودٌ في DmService

- **الشدّة:** P2 (أُصلِح · رقعةُ v2.474.1)
- **المجال:** الأداء
- **الوصف:** `DmService::threadRows` كان يجلب آخرَ رسالةٍ لكلِّ خيطٍ باستعلامٍ منفصلٍ لكلِّ خيط.
- **الدليل:** `DmService::threadRows` (`->first()` داخلَ `map` على المفاتيح).
- **الأثر:** محدودٌ بعددِ خيوطِ مستخدمٍ واحد، لكنّه نمطُ N+1 قابلٌ للإغلاق.
- **الجذر:** استعلامٌ لكلِّ خيطٍ لجلبِ آخرِ رسالة.
- **الإصلاح:** استعلامُ تجميعٍ واحدٌ يعطي آخرَ وقتٍ لكلِّ خيط (`MAX(created_at)`)، ثمّ استعلامٌ
  واحدٌ محدودٌ يجلب صفوفَ `(thread_key, created_at=آخرُ وقت)` لكلِّ المفاتيح دفعةً، ويُختار الأحدثُ
  `id` عند تساوي الثانية — فيُحفَظ ترتيبُ «آخرِ رسالة» (created_at ثم id) حرفاً، على SQLite وMySQL
  سواء. لا استعلامَ لكلِّ خيط.
- **اختبارُ الانحدار:** `ZeroLooseEndsHardeningTest::test_thread_rows_query_count_is_bounded_regardless_of_thread_count`
  (تساوي العددِ عند ١٠ و٣٠ خيطاً) + `test_thread_rows_preserve_most_recent_first_ordering`.
- **الحالة:** ✅ FIXED
