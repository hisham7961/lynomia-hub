# 07 — الأداء

## N+1

- نماذجُ الكيان 360 تستعمل `hub_ref_labels` (بحثُ أسماءٍ دفعةً واحدة) لتفادي N+1 في عرضِ
  المراجع؛ والعلاقاتُ تُحمَّل بـ`with(...)`.
- **حاجزُ N+1 حرِج = 0.**

## AUDIT-7 — N+1 محدودٌ في DmService (P2، موثّقٌ لا مُصلَح)

`DmService` يجلب آخرَ رسالةٍ لكلِّ خيطٍ باستعلامٍ لكلِّ خيط. **محدودٌ بعددِ الخيوطِ** (زملاءُ
مستخدمٍ واحد، عشراتٌ لا آلاف)، فليس حاجزاً مؤسّسيّاً. مُوثَّقٌ في سجلِّ الدَّين الفنّيّ؛ إصلاحُه
(تجميعُ آخرِ الرسائل باستعلامٍ نافذيٍّ واحد) تحسينٌ لا ضرورةَ إصدار.

## القوائمُ غيرُ المحدودة

### AUDIT-3 — نافذةُ رسائلِ الحاوية (P1، أُصلِح)

`CollaborationController`/`ConversationController` وغرفةُ المشروع كانت تحمّل **كلَّ** رسائلِ
القناةِ (`$conv->messages`) بلا حدّ — قناةٌ طويلةٌ تُحمّل آلافَ الصفوف. أُضيف
`Conversation::rootMessages(int $limit = 300)`: أحدثُ N جذورٍ (`whereNull('parent_id')`) مع
`with('user','replies.user')`، بترتيبٍ حتميٍّ تنازليٍّ ثمّ معكوسٍ لعرضٍ زمنيٍّ صاعد. طُبِّق في
ثلاثة مواضع. اختبارُ الانحدار: `test_conversation_root_messages_are_bounded_and_chronological`
(6 رسائل → نافذةُ 3 = م4/م5/م6).

### AUDIT-8 — قائمةُ `inventory_items` في صفحةِ المطابقة (P2، موثّقٌ لا مُصلَح)

صفحةُ مطابقةِ المخزون الإداريّة تجلب `inventory_items->get()` بلا صفحات. **محدودةٌ بعددِ الأصول**،
وصفحةٌ إداريّةٌ لا واجهةُ عميل. القرارُ: **عدمُ الإصلاح** — `$items` تُغذّي `$counts` (groupBy)
و`$itemCodes` معاً، فترقيمُها يستلزم جراحةَ عرضٍ بمخاطرةِ انحدار تتجاوز فائدةَ الإصدار. موثّقٌ
per §114/§119.

## اجتيازُ الرسم

- `RelationshipProjection::expand()` محدودٌ صراحةً: `max_hops=3`, `max_nodes=120`, ويُعلِّم
  `capped` عند البلوغ؛ حوافُّ المحطة→المشروع المُشتقّة **ورقيّة** (لا اجتيازَ أعمق).
- **مساراتُ اجتيازٍ غيرِ محدودة = 0.**

## الخلاصة

| البند | العدد |
|---|---|
| حاجزُ N+1 حرِج | 0 |
| حاجزُ قائمةٍ مؤسّسيّةٍ غيرِ محدودة | 0 |
| مساراتُ اجتيازِ رسمٍ غيرِ محدودة | 0 |

بندان أداءٌ محدودان (AUDIT-7، AUDIT-8) مُوثَّقان P2 غيرَ حاجزَين.
