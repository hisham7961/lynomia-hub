# 08 — مُفسِّرُ الصلاحيّة الفعّالة (§12/§59/§60/§93)

`App\Support\PermissionInspector` — طبقةُ قراءةٍ **تفوّض ولا تكرّر**: كلُّ قرارٍ من `hub_can`/
`hub_flag`/`PortalGuard`/`hub_scope`/`hub_field_mode`. لا قرارَ سماحٍ محلّيّ.

## الواجهة

| الدالّة | تُعيد |
|---|---|
| `explain(User, module, op)` | `{allowed, state, reason, chain[]}` — قرارٌ + سلسلةُ سبب |
| `allows(User, module, op)` | `bool` — القرارُ الفعّالُ المجرَّد (يطبّق حدَّ العميل) |
| `moduleMatrix(User)` | كلُّ وحدةٍ × v/a/e/d بقيمها الفعّالة + سببُ منعِ العرض، مجموعةً |
| `navigation(User)` | `{visible[], hidden[]}` — ولكلِّ مخفيّةٍ سببُها وحالتُها |

## سلسلةُ السبب (§59)

`explain('apps','v')` لموظفٍ لا يملكها:
```
✓ الوحدة — «التطبيقات» (apps) — جدول applications
✓ الدور — الدور: موظف اختبار
✗ المصفوفة [apps][v] — غيرُ مضبوطٍ في مصفوفةِ الدور
⇒ DENY [DENIED_ROLE] الدور «موظف اختبار» لا يمنح apps.v
```

لعميلٍ لوّثت مصفوفتُه:
```
✓ الوحدة — «التطبيقات» (apps)
✗ نوعُ الحساب — حسابُ عميلٍ — الوحدةُ داخليّةٌ خارجَ قائمةِ البوّابة (يعلو على المصفوفة)
⇒ DENY [DENIED_CLIENT] حدُّ حساب العميل يمنع الوحدةَ الداخليّةَ مهما كانت المصفوفة
```

## الحالات (§13)

`ALLOWED` · `DENIED_ROLE` · `DENIED_CLIENT` · `DENIED_NO_ROLE` · `OWNER` · `FLAG_GOVERNED` ·
`UNKNOWN_MODULE`. لا تُطوى في «غير مرئيّ».

## الأداء (§88/§89)

بلا استعلامٍ لكلِّ وحدة: `hub_can`/`hub_flag` يقرآن الدورَ المُحمَّل، و`hub_company_ids`/
`hub_client_ids` يقرآن سماتِ المستخدمِ المُحمَّلة. `moduleMatrix` تحسبُ من التهيئةِ والمصفوفةِ في
الذاكرة. منتقي التشخيصِ يحمّل أعمدةً خفيفةً فقط، ومعاينةُ الدورِ تُرقّم المستخدمين.

## تقريرُ الوصولِ الفعّال (§93)

`navigation()` + `moduleMatrix()` + ملخّصُ النطاق يشكّلان تقريرَ الوصولِ الآمن لأيِّ مستخدمٍ
داخليّ: الوحداتُ المرئيّة/المخفيّة، حقوقُ التعديل، النطاقات، والأسباب — بلا أسرار.
