# 09 — الأمن (§86/§87/§104)

## حمايةُ إدارةِ الصلاحيّات نفسِها

- محرّرُ الأدوار (`RoleController`) وشاشةُ التشخيص (`AccessController`) ومعاينةُ الدور: **مالكٌ
  حرفيّاً** (`abort_unless(hub_is_owner(), 403)`). حسابُ العميل: ٤٠٤ من `PortalGuard` (لا كشفَ
  وجود). الموظفُ الداخليُّ غيرُ المالك: ٤٠٣.
- إدارةُ المستخدمين محكومةٌ براية `users`؛ غيرُ المالكِ لا يمنح ملكيّةً (`guardEscalation`).

## حدُّ حساب العميل يعلو (§37/§73/§109)

حتى لو لوّثت مصفوفةُ العميلِ بصلاحيّةٍ داخليّة، `PortalGuard`/`MobilePortalGuard`/`resolveApi`
تحصره في `MODULE_ALLOW` — على الويب و`/api/v1` و`/api/mobile/v1` بمصدرٍ واحد. محروسٌ بـ
`test_inspector_client_boundary_overrides_polluted_matrix`. **تسريبٌ داخليٌّ للعميل عبر خطأِ محرّرٍ = 0.**

## تصعيدُ المصادقة (§44)

منحُ رايةٍ خطرة (`users/secrets/copySec/exp/audit/mobile`) أو توسيعُ النطاق (`proj→all`) يتطلّب
`hub_require_stepup` — محرّكُ التصعيدِ القائم، لا آليّةَ ثانية.

## أثرُ التدقيق (§42/§43)

كلُّ مسٍّ بالأدوار يُدوَّن (`hub_audit('… دور', 'roles', …)`) بفرقٍ محدود (`وحدة+/راية+/حقل+`)
يحمل «قبل» و«بعد» — بلا أسرار. شاشةُ التشخيصِ قراءةٌ محضةٌ لا تكتب.

## سلامةُ آخرِ مالك (§87)

محرّرُ الأدوار يمنع تعديلَ/حذفَ دورِ المالكِ ونزعَ ملكيّته؛ و`UserController` يقفل تغييرَ دورِ/حالةِ
آخرِ مالكٍ نشط. مُدقَّقٌ سلفاً — لا حاجةَ لإضافة.

## بوّابةُ سلامةِ الأمن (§104) — كلُّها صفر

تسريبُ صلاحيّةٍ عبرَ الشركات = `0` · تسريبٌ داخليٌّ للعميل = `0` · تصعيدُ دورٍ = `0` · تسريبُ
إدارةٍ للمالكِ حصراً = `0` · تسريبُ قواعدِ حقلٍ = `0` · تعارضُ خبيئةٍ عند تغيير الدور/النطاق = `0`
(المُفسِّرُ يحسب حيّاً من الدورِ المُحمَّل، فلا نافذةَ خبيئةٍ قديمة · §40).
