# 07 — واجهةُ إدارةِ الصلاحيّات (§14-26/§63-66)

## محرّرُ الأدوار (قائمٌ وقانونيّ — لم يُستبدَل · §3/§26)

`RoleController` + `resources/views/roles/form.blade.php` (مالكٌ حصراً):
- **مصفوفةٌ مولَّدةٌ من `config('hub.modules')`** عبر `groupedModules()` — مجموعاتُ `config/hub_nav`
  + التقاطُ الباقي في «أخرى». **كلُّ وحدةٍ إنسانيّةٍ حاضرة** عدا `users` (محكومةٌ بعلَم). لا قائمةَ
  مثبّتة. محروسٌ باختبار `test_role_editor_covers_every_module_except_users` (§16).
- خاناتُ `v/a/e/d` بعناوينَ عربيّة، مجموعةً بمجموعاتِ التنقّل (§15). قسمُ الرايات مستقلّ (§17).
  قسمُ قواعدِ الحقول مستقلّ (§19).
- **الكتابةُ تستلزم العرض** (§57): أيُّ عمليّةٍ تُفعّل `v` تلقائيّاً — محروسٌ باختبار
  `test_saving_mutation_without_view_auto_enables_view`.
- **حفظٌ ذرّيٌّ مُدقَّق:** يتحقّق من مفاتيحِ الوحدات، يكتب `is_owner=false`، يُدوّن أثرَ تدقيقٍ بفرقٍ
  محدود (`وحدة+ apps (v)`)، ويطلب تصعيدَ مصادقةٍ عند رايةٍ خطرةٍ أو توسيعِ نطاق (§41/§42/§43/§44).
- **استنساخُ دور** (§62) قائم. قوالبُ بدايةٍ (§55) قائمة.

## شاشةُ تشخيصِ الوصول (جديدة · `/admin/access` · مالكٌ حصراً)

طبقةُ عرضٍ فوق `PermissionInspector` — لا محرّكَ ثانٍ:
- **منتقي مستخدم** → ملخّصُ الوصول (حساب/دور/شركات/عملاء/مشروع/حالة · §20/§21).
- **مصفوفةٌ فعّالة** بالوحدات (v/a/e/d) مجموعةً + سببُ منعِ العرض (§22).
- **معاينةُ التنقّل** الفعّال: مرئيّ مقابل مخفيّ ولكلِّ مخفيّةٍ سببُها (§60).
- **فحصٌ نقطيّ** (وحدة · عمليّة) → قرار `ALLOW/DENY` + **سلسلةُ السبب** خطوةً خطوة (§59).

## معاينةُ الدور (§24 · `/admin/access/role/{role}`)

حسابٌ لا انتحال: يعرض ما يبلغه دورٌ افتراضيٌّ داخليٌّ بهذا الدور (وحداتٌ مرئيّة + مصفوفة) + المستخدمون
المسنَدون (مُرقَّمون · §23/§89). لا إنشاءَ مستخدمٍ ولا جلسةَ انتحال — محروسٌ باختبار
`test_access_role_preview_is_computed_without_creating_a_user`.

## قابلةٌ للاستعمالِ بلا كود (§63/§115)

عناوينُ عربيّةٌ للوحدات، أسبابٌ منطوقة، بلا فكِّ JSON. الجوابُ على «ماذا يرى هذا الموظف؟» و«إن
فعّلتُ apps.v هل سيراها؟» صار حتميّاً بنقرةٍ في الشاشة.
