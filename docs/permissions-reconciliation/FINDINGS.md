# FINDINGS — نتائجُ مطابقةِ الصلاحيّات (§94)

التصنيف: **P0** تصعيدُ امتياز/تسريبُ بيانات · **P1** صلاحيّةٌ مُنِحت فتعذّر الوصول أو وحدةٌ غيرُ
مصرَّحةٍ نُفِذت أو عيبُ إدارةٍ كبير · **P2** التباسُ إدارةٍ/تشخيص · **P3** تجميليّ/توثيقيّ.

**الملخّص: P0 = 0 · P1 = 0 · P2 = 1 (مُعالَج) · P3 = 1 (موثّق).**

## PR-1 — العيبُ المُبلَّغ (Projects تُرى، Applications لا) — **ليس عيباً بنيويّاً**

- **الشدّة:** P2 (التباسٌ/تشخيص — مُعالَج بالإضافة)
- **المجال:** فهمُ الصلاحيّة / التشخيص
- **الوصف:** المالكُ لا يستطيع تحديدَ سببِ رؤية/إخفاء وحدةٍ لموظف.
- **الدليل (مُثبَت §6):** المفتاحُ القانونيُّ لـ«التطبيقات» = `apps`. تجريبيّاً: دورٌ يمنح
  `apps.v=1`+`projects.v=1` لموظفٍ داخليّ ⇒ `hub_can apps.v = true` وapps **يظهر** في `hub_nav`
  وبحثِ IA تماماً كـprojects. ثلاثُ جولاتِ تدقيقٍ متوازية أكّدت تماثلَ المسارَين في كلِّ سطح.
- **الجذر:** غيابُ مُفسِّرٍ للصلاحيّة الفعّالة. العرَضُ سببُه أحدُ سلوكين صحيحين: (أ) `apps.v` لم
  يُمنَح فعلاً، أو (ب) حسابٌ عميلٌ (`apps ∉ MODULE_ALLOW`).
- **المعالجة:** `PermissionInspector` + شاشةُ تشخيصِ الوصول تُظهران القرارَ الفعّالَ وسببَه؛ +
  اختباراتُ مطابقةٍ بنيويّة تُثبّت التماثل. **لم يُغيَّر سلوكُ apps** (صحيح)، **ولم تُمنَح وحدةٌ
  للجميع** (§116).
- **اختبارُ الانحدار:** `test_applications_visibility_follows_view_permission`،
  `test_projects_and_applications_parity`، `test_inspector_client_boundary_overrides_polluted_matrix`.
- **الحالة:** ✅ RESOLVED (بالإضافة)

## PR-2 — تفضيلُ `nav.hidden` قد يُخفي بندَ وحدةٍ في الوضع الكلاسيكيّ

- **الشدّة:** P3 (توثيقيّ — سلوكٌ صحيح)
- **المجال:** التنقّل
- **الوصف:** الوضعُ الكلاسيكيُّ للشريط يحترم تفضيلَ `nav.hidden` الشخصيّ، فقد يخفي بندَ وحدةٍ بينما
  `hub_can` يسمح — وتبقى الوحدةُ مُكتشَفةً عبر البحث/الرابط المباشر/الشريط الفضائيّ.
- **الحكم:** **تخصيصُ مستخدمٍ لا حاجزُ صلاحيّة** — سلوكٌ صحيح. موثّقٌ في `06-navigation-parity`
  والمُفسِّر كي لا يُخلَط بالمنع.
- **الحالة:** 📋 DOCUMENTED (لا تغيير)
