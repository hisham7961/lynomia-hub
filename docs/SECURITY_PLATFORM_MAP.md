# خريطة منصة الأمن المؤسسية — جرد القائم وتصنيف الفجوات

> ناتج التدقيق الأمني الثلاثي الإلزامي (المصادقة/الجلسات/الأجهزة · المركز/الأحداث/التدقيق/الطوارئ · البيانات/الأسرار/API) قبل أول سطر — v2.367.0.
> القاعدة: **قائمٌ قويّ يُحفَظ · ضعيفٌ يُحسَّن · ناقصٌ يُكمَل · غائبٌ يُبنى — ولا ثاني لأي شيء.**

## أ) قائم وقويّ — يُعاد استخدامه حرفياً (لا يُكرَّر)

| القدرة | المصدر القانوني الواحد |
|---|---|
| سلسلة تدقيق موقَّعة بالتجزئة (كشف عبث حقيقي: رأس ذرّي + مشي بنيوي + إعادة تجزئة) | `audits` + `AuditEntry` + `hub:audit-verify` |
| طمس الأسرار في التدقيق ببصمة لا نجوم | `Auditable::auditRedact` + `Audit::MASKED` |
| العمود الفقري للتفويض (مالك/مصفوفة/رايات/قواعد حقول/تنطيق ثلاثي شركة+مشروع+عميل) | `hub_can/hub_flag/hub_field_mode/hub_scope` |
| رادار رفض الوصول (403 + تخمين روابط) بتقليم مضبوط | `access_denials` + `SecurityRadar` + `AccessRadar` |
| نبض الجلسات وإبطالها الحي عن بعد + فحص الحساب كل طلب | `sessions_log` + `SessionSentry` |
| تعلّم ألفة العناوين لكل مستخدم | `user_ips` + `LoginSentry` |
| قفل حساب ذرّي + تصعيب تعداد الحسابات + إعادة توليد الجلسة | `AuthController` |
| خزنة مشفَّرة فعلاً (AES عبر Crypt) بكشفٍ خادمي مبوَّب مدقَّق | `vault_secrets` + `EncryptedOrPlain` + `revealSecret` |
| صانع/مدقِّق مُحكم (قفل صف + نسخة تفاؤلية + صلاحية المعتمِد + تنطيق الهدف + نهائية مزدوجة) | `approvals` + `ApprovalDecisionController` |
| محرك أتمتة بأحداث دلالية وقوالب لا تسرّب و«صندوق رمل» | `HubEvents` + `FlowRunner` + `flows` |
| سجل حوادث كامل الشكل (فتح→احتواء→استعادة→إغلاق بتقرير، قائد، جذر، وقاية، مراجعة) | وحدة `incidents` |
| قفل طوارئ يطرد الجلسات الحية ويعلّق API | `security.lockdown` + `HubMaintenance` |
| مركز أمن قائم بوضعية 16 فحصاً ورادار وجلسات | `SecurityController` + `SecurityPosture` |
| SSRF مصدود بتثبيت DNS، ترويسات أمن، كوكيز آمنة، حراس اختبارات كتابة شاملة | `Uptime`/`SecurityHeaders`/`WritingRoutesAuthz*` |

## ب) عيوب مؤكدة تُصلَح فوراً (اختبار يفشل أولاً — المرحلة ب v2.367.0)

1. سكّ رموز API: بلا تدقيق، بلا انتهاء افتراضي، كامل الصلاحيات، يتجاوز 2FA — يُدقَّق (إنشاء/تدوير/إبطال) ويُفرَض انتهاء افتراضي مضبوط ويُتاح تعطيله طارئياً.
2. لا حدّ معدل على كشف السر والتصدير الفردي والدفعي — تُضاف حدود بسابقة سلّم المستودع.
3. غرفة البيانات: قوائم/إبطال بلا عزل منشئ + صفر تدقيق — تنطيق وتدقيق.
4. تثبيت/حل التعليق يتجاوز تنطيق السجل الأم — يُسدّ بنمط `guardTarget` الموجود في الملف نفسه.
5. `hub_ref_options` بلا تنطيق في نموذج يوم العمل ودمج المنتجات — يُعوَّض في الموضعين.
6. رفع المرفقات بصلاحية عرض لا تعديل + قائمة امتدادات أضيق من نظيرتها — يوحَّدان على الأشد.
7. أحداث مصادقة غائبة عن التدقيق (دخول ناجح، خروج، تغيير كلمة، فشل TOTP، رفضٌ بعد كلمة صحيحة، دورة حياة الرمز، روابط الغرفة).
8. «هذا أنا — متابعة» بلا أثر خادمي — يصير تأكيداً خادمياً مدقَّقاً يبني ثقة الجهاز.

## ج) يُبنى امتداداً (المراحل ب→د)

- **هوية الجهاز وثقته** (غائبة كلياً): كوكي جهاز + `user_devices` بحالات (موثوق/معلّق/مبطَل) وربط الجلسات به وإبطال جهازٍ بجلساته — إشارة جديدة لحارس الدخول.
- **جلساتي للمستخدم** (الإبطال اليوم للمالك فقط): بطاقة في الملف الشخصي بإبطال ذاتي.
- **محرك خطر مفسَّر**: نواة `ActivityController::riskProfile` القائمة تصير `Support\Risk` بجلسةٍ ودرجةٍ وعواملَ مسمّاة وخطٍّ زمني — تُعرض ولا تعاقب آلياً.
- **تصعيد المصادقة Step-Up**: نافذة تحقق (كلمة/TOTP) قبل: كشف سرّ، قفل الطوارئ، تعديل دور، إطفاء 2FA لآخر، تصدير فوق عتبة — بنافذة صلاحية مضبوطة.
- **مصادقة تكيفية**: فرض تسجيل 2FA على الأدوار الخطرة (كان تقريراً فقط)، وإشارات الجهاز الجديد ترفع الاحتكاك بدل «لافتة تُغلق».
- **تصنيف البيانات**: مرساة `files.secrecy` الزخرفية تصير مُنفَّذة (سرّي ⇒ تدقيق تنزيل + Step-Up حسب السياسة) وتمتد لمرفقات السجلات.
- **حوادث أمنية**: أحداث المستوى الحرج تفتح حادثة في `incidents` القائمة بنوع أمني — لا محرك حوادث ثانٍ.
- **حِزم استجابة**: `hub.events` يُضاف له users/vault/roles وأفعال أمنية تُطلق `FlowRunner` — والقواعد `rules.mod` تكسب الجداول الأمنية.
- **أمن المستخدم 360°/خريطة الهوية/نطاق الانكشاف**: امتداد شاشة النشاط القائمة بعلاقات فعلية لا رقم أسود.
- **مفاتيح طوارئ مفصولة**: تعطيل تصدير/سكّ رموز/مشاركة خارجية — كلٌّ بأثره الظاهر، لا زرّ واحد خطر.
- **احتفاظ**: تقليم `sessions_log`/`user_ips` في الأتمتة اليومية (السجل التدقيقي يبقى للأبد عمداً).
- **Passkeys/WebAuthn** (لا أثر إطلاقاً): تُقيَّم في المرحلة ج — إن أمكن تنفيذٌ آمن بلا مكتبة خارجية (سياسة الاستضافة) نُفِّذ، وإلا وُثِّق حرفياً كملحق مؤجل بأسبابه.

## ملحق ج — Passkeys/WebAuthn (مُنفَّذٌ في v2.379.0 — لا مؤجَّلاً)

كان القرارُ الأوّل تأجيلَها خشيةَ أن يتطلّب تنفيذُها الآمنُ مكتبةَ خادمٍ ثقيلة.
والمراجعةُ الأدقّ بيّنت أن **مسارَ التحقّق (assertion) قابلٌ للتنفيذ الآمن بلا
مكتبة** بثلاثة قرارات:
- **`attestation:none`** (المعيارُ لمفاتيح المنشأة الداخلية) — يُلغي التحقّقَ من
  ثقة الصانع، وهو أخطرُ وأثقلُ جزء.
- **ES256 فقط** (P-256) — مسارُ COSE→PEM واحدٌ مُعلَنٌ ومُختبَر.
- **التوقيعُ يُتحقَّق بـ`openssl`** لا بتعميةٍ يدوية — والتحليلُ (CBOR/COSE/DER)
  تحليلُ بايتاتٍ خطؤه يُفشِل التحقّقَ لا يتجاوزه.

فالتنفيذُ (`app/Support/Webauthn.php` + `PasskeyController`): محلّلُ CBOR مُصغَّرٌ
مُختبَر، وتحويلُ COSE ES256 → PEM، وتحقّقٌ يفرض التحدّيَ والأصلَ والنوعَ وrpIdHash
وحضورَ المستخدم والتوقيعَ وتصاعديّةَ العدّاد. **مُثبَتٌ بمُصادِقٍ افتراضيّ** يقبل
الصحيحَ ويرفض المعبوث (تحدٍّ/أصل/توقيع/عدّاد/نوع). يُبنى على `finishLogin`
و`StepUp` القائمين — لا محرك مصادقةٍ ثانٍ. **لا بندَ مؤجَّلٌ بعده في منصة الأمن.**

## د) حدود صريحة (أمانة لا تقصير)

- **لا مصدر جغرافيا IP في البنية** (لا GeoIP محلي ولا ترويسات مزود): «السفر المستحيل» يُبنى على **تغيّر عنوان الشبكة أثناء الجلسة** وسرعته، والبلد/المدينة يبقيان خلف مزوِّدٍ اختياري يُضبط لاحقاً — لا ادعاء دقةٍ لا نملكها، والموقع الدقيق يبقى ملك نطاق الميدان (لا خلط مع تتبع المندوبين).
- **JIT privilege**: نقطة الامتداد موثقة على القائم (اعتماد + انتهاء دور) دون تنفيذٍ يكسر RBAC الحالي — كما سمحت المواصفة نصاً.
- درجة الوضعية تبقى مفسَّرة البنود (لا رقم اعتباطي)، وترجيح الفحوص يُحسَّن.

## حالة المرحلة د (شُحن جزئيّاً — الباقي موثَّقٌ لا منسيّ)

**شُحن في v2.369.0**: ضبطُ التصدير الجماعي (عتبةٌ تُلزم تصعيدَ المصادقة وتوسم
«تصدير كبير»)، وسياسةُ احتفاظٍ لبيانات الأمن (تقليمُ الجلسات المُنهاة القديمة
وألفةِ العناوين البائتة في الكنس اليومي، بمدّتين مضبوطتين — والسلسلةُ التدقيقيةُ
تبقى للأبد عمداً).

**شُحن في v2.372.0**: **تصنيف البيانات المُنفَّذ** (تنزيلُ «سري» حدثُ وصولٍ
حسّاسٍ مُوسَم بتصعيدٍ حسب السياسة) و**الحوادثُ الأمنية** (حدثُ المستوى الحرج
يفتح حادثةً في `incidents` بنوعٍ أمنيّ، والمركزُ يعرض المفتوحة).

**شُحن في v2.378.0 — إغلاقُ المتبقّي كلِّه (امتداداً لا تكراراً):**
- **حِزم الاستجابة**: `hub.events` كسب كتلَ `users`/`vault`، وأفعالُ الأمن
  تُطلق `FlowRunner::fire` — `user.sessions_revoked` (SecurityController::revokeUser)
  و`vault.revealed` (ModuleController::revealSecret). و`rules.mod` كسب `users`
  للتنبيه المجدول. (تصعيدُ الأدوار خارج التدفّقات عمداً: `roles` يديره RoleController
  لا سجلُّ الوحدات فلا `hub_mod` لها — وله Step-Up وأثرُ «قبل/بعد» أصلاً.)
- **مفاتيحُ الطوارئ المفصولة**: `security.freeze_exports` و`security.freeze_tokens`
  — كلٌّ يصدّ فعلَه بالرمز ٤٢٣ (SecurityController::freeze + الإنفاذ في
  ModuleController::export وProfileController::tokenStore/tokenRotate)، التفعيلُ
  فوريٌّ ورفعُه يتطلب Step-Up.
- **اللوحة الموحدة وخريطة الانكشاف**: `Support\SecurityExposure::map()` — نطاقُ
  أثرِ الحسابات عالية الامتياز بعلاقاتٍ فعلية (أدوار/جلسات/أجهزة)، درجةٌ مفسَّرةُ
  العوامل، معروضةٌ في مركز الأمن.

**لا متبقٍّ موثَّقٌ في منصة الأمن (أ–د مكتملة).** يبقى ملحقُ Passkeys/WebAuthn
مؤجَّلاً بأسبابه أعلاه (البند ٨٣: خطةُ توافقٍ آمنة لا ترقيةٌ عمياء).
