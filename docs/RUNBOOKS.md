# كتيّبات التشغيل — Lynomia Business Hub

> إجراءاتٌ مختصرة للأعطال الكبرى. كلُّ كتيّب: **الأعراض** (أين تراه في مركز التشغيل) → **التشخيص** (أوامرُ وشاشات) → **المعالجة** → **التحقق**. تُقرأ من مركز التشغيل (`/admin/ops/runbooks`) ومن هذا الملف.
>
> المصدرُ الواحد للصحّة: `/healthz` (عامّ، حالاتٌ فقط) و`/admin/ops/health` (للمالك، بالتفاصيل) — كلاهما من `App\Support\Health`.

## 1) المجدولات متوقّفة (cron)

**الأعراض:** مكوّن «المجدولات» في مركز التشغيل `UNAVAILABLE` أو `DEGRADED`؛ نبضات «عامل التسليم»/«الأتمتة اليومية» متأخرة؛ الإشعارات الخارجية لا تصل؛ المتكررات لا تتولّد.

**التشخيص:**
```bash
php artisan schedule:list                 # ما يجب أن يعمل ومتى
php artisan schedule:run                  # تشغيلٌ يدويّ فوريّ — إن عمل فالمشكلة في cron نفسه
crontab -l                                # هل السطر موجود؟
tail -50 storage/logs/laravel.log
```
السطر المطلوب في cron الخادم (مرة واحدة):
```
* * * * * cd /path/to/hub && php artisan schedule:run >> /dev/null 2>&1
```

**المعالجة:** أضف/أصلح سطر cron (cPanel → Cron Jobs). على استضافةٍ مشتركة تأكّد أن مسار `php` هو نسخة 8.2+ (`which php`). تشغيلٌ يدويّ لتفريغ المتراكم: `php artisan hub:outbox` ثم `php artisan hub:automation`.

**التحقق:** في مركز التشغيل تعود النبضات «✓ تعمل» خلال ٥ دقائق، و`/healthz` يعرض `scheduler: HEALTHY`.

**ما يحدث تلقائياً (v2.399):**
- **فشلُ أيّ مهمةٍ مجدولة** (رمزُ خروجٍ غيرُ صفريّ) يصل مركزَ الأخطاء ويُشعر المالكين والمراقبين، وتُكتب نبضتُها `fail`؛ فشلُ `hub:audit-verify` يفتح **حادثةً أمنية**.
- **مفتاحُ الرجل الميّت** (`ops.watchdog`): إن لم تنبض المجدولاتُ كلُّها، يُشعَر المالكون من أول زيارة ويبٍ (مرّةً في اليوم حتى تعود) — لأن المنبّهَ نفسَه يعمل بالـcron.
- **مزلاجُ withoutOverlapping** ينتهي بعد ٢٠ دقيقةً لمهامّ الخمس دقائق و٤ ساعاتٍ لليوميّة؛ تشغيلٌ قُتل لا يحبس الصادرَ يوماً. وأقفالُه في `storage/framework/cache/locks` لا يمسحها `optimize:clear`.
- الصادرُ الفاشل مؤقّتاً يُعاد آلياً (٥ ← ٣٠ ← ١٢٠ دقيقة، `outbox.max_attempts`) ثم يصير `failed`؛ `hub:outbox --retry` يُعيد النهائيّ.

## 2) قاعدة البيانات لا تُجيب

**الأعراض:** `/healthz` يردّ `503` و`checks.db = fail`؛ صفحاتُ الدخول تعرض خطأً؛ مركزُ الأخطاء (إن فُتح) يمتلئ بـ`DATABASE / CRITICAL`.

**التشخيص:**
```bash
php artisan tinker --execute='DB::select("select 1");'
mysql -u <user> -p -h <host> -e 'select 1'
df -h                                    # قرصٌ ممتلئ يوقف MySQL
```

**المعالجة:** أعد تشغيل خدمة MySQL من لوحة الاستضافة؛ تحقّق من بيانات `.env` (`DB_*`)؛ حرّر مساحةً إن امتلأ القرص (`storage/app/backups` أولاً — تدوير ١٤ نسخة). **لا** تشغّل `migrate:fresh`/`migrate:refresh` (محجوبان بـ`SchemaGuard`).

**التحقق:** `/healthz?probe=ready` يردّ `200`، ومكوّن «قاعدة البيانات» `HEALTHY` بزمنٍ أقل من ٥٠٠ms.

## 3) التخزين معطّل أو ممتلئ

**الأعراض:** مكوّن «التخزين» `DEGRADED` (≥85٪) أو `UNAVAILABLE` (غير قابل للكتابة/≥97٪)؛ رفعُ المرفقات يفشل؛ أخطاء `STORAGE / HIGH`.

**التشخيص:** بطاقة «من يستهلك القرص» في مركز التشغيل (النسخ الاحتياطية، المرفقات، السجلات، مخبأ الإطار).
```bash
du -sh storage/app/backups storage/app/hub storage/logs storage/framework
ls -la storage/app storage/logs                    # الصلاحيات
```

**المعالجة:** احذف نسخاً احتياطية قديمة بعد نقلها خارج الخادم؛ `php artisan optimize:clear` لمخبأ الإطار؛ قلّل `LOG_DAILY_DAYS`؛ صحّح الملكية/الصلاحيات (`storage/` قابلة للكتابة لمستخدم PHP).

**التحقق:** مكوّن «التخزين» يعود `HEALTHY`؛ رفعُ مرفقٍ تجريبيّ ينجح.

## 4) تكاملٌ خارجيّ منقطع (أودو / تلجرام / بريد / ويبهوك)

**الأعراض:** مركزُ التكاملات يعرض `FAILED`/`DEGRADED` مع «آخر فشل» و«السبب»؛ مكوّن «التكاملات» أو «الصندوق الصادر» أو «الويبهوك الصادر» متدهور.

**التشخيص:**
- أودو: زر «اختبار الاتصال» في شاشة خوادم أودو (يعيد: مصادقة/وصول/إصدار/زمن).
- تلجرام/بريد: مركز المراسلة → «اختبار» ثم «إعادة الفاشل».
- ويبهوك صادر: صفحة الاشتراك → سجل المحاولات (رمز HTTP، الزمن، الخطأ)، وزر «اختبار».
- ويبهوك وارد: شاشة نقاط الاستقبال → آخر الأحداث والتوقيع.

**المعالجة:** الاشتراكُ الموقوف مؤقتاً بعد ١٠ إخفاقات يستأنف تلقائياً بعد ساعة، أو فوراً بإعادة إرسالٍ يدوية ناجحة. رسائل الصندوق الفاشلة: `php artisan hub:outbox --retry`. مهلاتُ أودو: ٣ث اتصال/١٢ث طلب — خادمٌ بطيء يُقال «لا استجابة» لا يُعلَّق.

**التحقق:** شارةُ التكامل تعود `CONNECTED` بعد أول نداءٍ ناجح (أودو خلال ٥ دقائق من النجاح).

## 5) اشتباهٌ في تسرّب مفتاح API أو حساب

**الأعراض:** السجل الأمني الموحّد (`/admin/security#secevents`) يعرض `AUTH_FAILURE`/`ACCESS_DENIED` من عناوين غريبة، أو استخدام API غير معتاد في مركز التكاملات.

**المعالجة (بالترتيب):**
1. **جمّد سكّ الرموز** من مركز الأمان (`security.freeze_tokens`) — يوقف فتح قنوات جديدة ويُبقي الإبطال.
2. **أبطل** المفتاح المشتبه من ملف صاحبه (حسابي ← مفاتيح API) أو دوّره.
3. **أنهِ جلسات** المستخدم من مركز الأمان (تُطرد فوراً).
4. عند الخطر الواسع: **قفل الطوارئ** — يقطع كل الجلسات ويعلّق سطح API كلَّه (يبقى دخولُ المالك من المتصفح).
5. راجع السجل الأمني بكود `SECRET_REVEALED`/`SENSITIVE_EXPORT`/`DATA_EXPORT` لمعرفة ما وصل إليه.
6. بعد الاحتواء: افتح حادثةً في وحدة الحوادث (نوع أمني) بالخط الزمني والإجراءات.

**التحقق:** `API_CREDENTIAL_REVOKED` و`SESSION_REVOKED` في السجل الأمني بمعرّف طلبك.

## 6) نشرٌ فشل أو أعقبه انهيار

**الأعراض:** بعد «Deploy HEAD Commit» شاشاتٌ بخطأ ٥٠٠، أو مكوّن «مخطّط القاعدة» `DEGRADED` (ترحيلات معلّقة)، أو أخطاء `Unknown column`.

**التشخيص:**
```bash
php artisan migrate:status | grep -i pending
php artisan hub:schema-check              # ما يقرؤه الكود ولا تملكه القاعدة (بلا تغيير)
php artisan about
```

**المعالجة:** `php artisan migrate --force` (كل الهجرات إضافية غير مدمّرة)، ثم `php artisan optimize:clear`. إن تغيّر `composer.lock`: `composer install --no-dev --optimize-autoloader`. للتراجع: انشر الـcommit السابق من Git Version Control — الهجراتُ الإضافية لا تُكسر بالكود الأقدم.

**التحقق:** `/healthz?probe=ready` = `200`، وشاشةُ «الترحيلات» في مركز التشغيل «✅ مطابقة»، وحزمةُ الدخول/القائمة/الحفظ تعمل يدوياً.

## 7) عاصفةُ أخطاء

**الأعراض:** مكوّن «الأخطاء» `DEGRADED`/`UNAVAILABLE`؛ إشعاراتُ «عطل جديد» (مسقوفة ٨ كل ١٥ دقيقة).

**المعالجة:** افتح مركز الأخطاء مصفّى بـ`sev=CRITICAL` ثم `HIGH`؛ اقرأ الصنف (قاعدة/تكامل/تخزين/إعداد) واذهب للكتيّب المناسب؛ «معرّف الطلب» يربط الخطأ بالتدقيق والرسائل الصادرة. حوّل الجذريَّ إلى مهمة من الشاشة نفسها.

## 8) النسخ الاحتياطي

**الأعراض:** نبضة «النسخ الاحتياطي» متأخرة أو نتيجتها `fail`.

**التشخيص:** `php artisan hub:backup` يدوياً — يطبع السبب (ترميز/قرص/صلاحيات). النسخ في `storage/app/backups/hub-*.json` (صلاحيات 0600، آخر ١٤).

**المعالجة والتحقق:** حلّ السبب ثم أعد التشغيل؛ اختبر الاستعادة على قاعدةٍ **منفصلة** (`php artisan hub:import <ملف>` على بيئة تجريبية) ووثّقها في وحدة «اختبارات الاستعادة». لا استعادةَ على الإنتاج بلا نسخةٍ أحدث منها.

**التشفير والتحقق (v2.399):**
- `backup.encrypt=1` (من القاعدة: `php artisan hub:set backup.encrypt 1`) يكتب النسخةَ `hub-<تاريخ>.json.enc` مشفَّرةً بمفتاح التطبيق. **احفظ `APP_KEY` خارج الخادم** (مدير كلمات مرور المنشأة) — بلا المفتاح لا تُفكّ النسخة، ومفتاحٌ مختلف يُرفض برسالةٍ صريحة لا بـ«0 سجل».
- `php artisan hub:backup --verify` يُعيد قراءةَ الملف ويفكّه ويعدّ سجلاته — تمرينُ استعادةٍ مصغّر يقوله رمزُ الخروج. زرُّ «نسخة الآن» في مركز التشغيل يقول «فشل» حين يفشل الأمر.
- النسخةُ تشمل جداولَ الوحدات كلَّها + جداولَ الأتمتة والاعتماد والتوقيع وبنودَ العروض وسلسلةَ التدقيق (`HubBackup::coveredTables()`)؛ ما استُثني عمداً مُعلَنٌ في `HubBackup::EPHEMERAL` ويحرسه اختبار.
- **خارج الخادم:** النسخةُ محلّيةٌ فقط حتى الآن — انسخ `storage/app/backups/` دورياً إلى مكانٍ آخر (rclone/SFTP من جهازٍ آمن)، ووثّق آخرَ نسخةٍ خارجية في وحدة «اختبارات الاستعادة». وضعيةُ الأمان تُنذر حين تشيخ آخرُ نسخةٍ ناجحة عن ٣٠ ساعة.
- نشرُ cPanel (`.cpanel.yml`) يأخذ نسخةً **قبل** الترحيل ويفحص المخطّط بعده.

## 9) بيئةٌ تجريبية أو نسخةٌ من الإنتاج للتحليل

**الخطر:** نسخةٌ من قاعدة الإنتاج على خادمٍ تجريبيّ تُرسل تلجرام وبريداً وويبهوك حقيقيةً وتطرق أودو.

**المعالجة:** في `.env` التجريبيّ ضع `HUB_OUTBOUND=off` ثم `php artisan optimize:clear` — كلُّ نداءٍ خارجيّ (رسائل، ويبهوك، مراقبة، استكشاف، أودو) يُرفض عند حاجز الخروج برسالةٍ تسمّي المفتاح. وضعيةُ الأمان تُظهر `APP_ENV`/`APP_DEBUG` الحاليَّين.

**التحقق:** `php artisan hub:outbox` يطبع فشلَ الرسائل بسبب `HUB_OUTBOUND=off` ولا يغادر شيءٌ الخادم.

## 10) بروفةُ الترقية قبل النشر (نسخةٌ من القاعدة)

**الخطر:** هجرةٌ تنجح على قاعدةٍ فارغة (كما في CI) وتسقط على قاعدة الإنتاج: عمودٌ ممتلئ يُضيَّق، نوعٌ لا يقبل ما فيه، أو `explicit_defaults_for_timestamp=OFF` (TECH_DEBT DI-05) — أو تنجح ويُكتشف فقدُ قيمةٍ بعد النشر.

**المعالجة:** بنسخةٍ من قاعدة الإنتاج و`APP_KEY` نفسِه (كي تُقرأ الأسرارُ المشفَّرة)، على الخادم أو محلياً بالشيفرة الجديدة:

```bash
mysql -e "CREATE DATABASE hub_rehearsal CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
mysqldump hub_prod | mysql hub_rehearsal
export DB_DATABASE=hub_rehearsal HUB_OUTBOUND=off      # لا رسائلَ ولا ويبهوك تغادر من البروفة
php artisan hub:backup --keep=1                        # الخطوةُ الأولى في .cpanel.yml نفسُها
php artisan migrate --force
php artisan optimize:clear
php artisan hub:schema-check                           # يجب أن يطبع «لا فروقات»
```

**التحقق:** أعدادُ الصفوف في الجداول الرئيسية (`users`, `clients`, `tasks`, `fin_documents`, `audits`) قبل الترحيل وبعده متساوية؛ آخرُ `hash` في `audits` لم يتغيّر؛ تسجيلُ الدخول على النسخة يعمل بكلمة المرور القديمة؛ ويبهوك قديمٌ يُفتح من الإعدادات ويُقرأ سرُّه. ثم `DROP DATABASE hub_rehearsal`.

> نُفّذت هذه البروفة لترقية v2.400 على مخطّط v2.399.1 ببياناتٍ ممثِّلة (سجل الإصدارات v2.400.2): ٧ هجرات في ٨٫٥ ثانية على قاعدةٍ صغيرة. على قاعدةٍ كبيرة، فهارسُ `created_at` على ~١٢٠ جدولاً تأخذ دقائق — نفّذ النشر خارج ساعات الذروة.

### بروفةٌ منفَّذة: v2.400.1 → v2.405.0 (٦ سبتمبر ٢٠٢٦)
**الأساس:** قاعدةُ MySQL أُنشئت بشيفرة الفرع الأساس `claude/arfaah-uzt2d9` (0401692، v2.400.1 — ما يُنشر على الخادم اليوم): 152 جدولاً، 177 هجرة، بيانات ممثّلة (عميل، مهمة منجَزة، حادثة أمنية بـmeta.kind، خطأ مجمَّع، ويبهوك بسرٍّ صريح، قاعدة تنبيه، سلسلة تدقيق).

**التسلسل المنفَّذ بشيفرة v2.405.0 (نفسُ خطوات `.cpanel.yml`):**
| الخطوة | النتيجة |

**حفظُ البيانات (كلُّها مطابقة قبل/بعد):** users · clients · tasks · incidents · error_events · alert_rules · webhooks · audits · **رأسُ سلسلة التدقيق (hash)** · **تجزئةُ كلمة مرور المالك**.

**الاحتياطاتُ الكسولة تعمل على الصفوف القديمة:**
- `incidents.kind` = NULL ⇒ القارئ يسقط إلى `meta` (لا ملءَ رجعيّ).

**الجداولُ الستّة الجديدة موجودة:** http_metric_buckets · error_occurrences · security_findings · audit_verifications · alert_instances · incident_links.
**الأعمدةُ الجديدة موجودة:** tasks.completed_at · error_events.assignee_id · audits.severity · api_tokens.last_ip · sessions_log.revoked_at · user_ips.first_seen_at · vault_secrets.rotated_at · alert_rules.cooldown_min · incidents.detected_at · access_denials.request_id.

**الأوامرُ الستّة على القاعدة المُرقّاة (exit=0):** hub:ops-snapshot (لقطةُ جاهزية + 12 عدّادَ جدول) · hub:security-snapshot (الدرجة 68٪ · 7 نتائج) · hub:alerts-evaluate · hub:audit-verify (السلسلة سليمة) · hub:quality-snapshot · hub:metrics-snapshot.

**١٥ شاشة تُجيب 200 في `APP_ENV=production` على القاعدة المُرقّاة:** /login · / · /admin/ops · /admin/security · /admin/security/{findings,identity,sessions,tokens} · /admin/audit · /admin/audit/coverage · /admin/errors · /admin/errors/logs · /admin/alerts · /workforce/overview · /admin/quality · /healthz.

> تُعاد هذه البروفة قبل كل نشرةٍ كبيرة بالخطوات أعلاه على نسخةٍ من قاعدة الإنتاج.

## 11) عاصفةُ تنبيهات (الجرسُ يدقّ ولا أحد يعرف لماذا)

**الأعراض:** مركزُ التنبيهات (`/admin/alerts`) يمتلئ بصفوفٍ `triggered`؛ إشعاراتٌ متكرّرة عن الشرط نفسِه؛ صفُّ «يستدعي تدخّلك» في `/admin/control` كلُّه من نوعٍ واحد.

**افهم أولاً — صفٌّ واحدٌ ليس حدثاً واحداً:** كلُّ صفٍّ في `alert_instances` مفتاحُه `dedup_key` **فريد**، وعمودُ `count` هو عددُ مرّات إطلاقِ الشرط نفسِه. عشرةُ صفوفٍ = عشرةُ شروطٍ مختلفة؛ صفٌّ واحدٌ بعدّادِ ٤٠٠ = شرطٌ واحدٌ يطرق. اقرأ العدّادَ قبل أن تعدّ الصفوف.

**التشخيص:**
```bash
php artisan hub:alerts-evaluate --dry    # معاينةٌ لا تكتب شيئاً — ما كان سيُطلق ويُحلّ
php artisan hub:alerts-evaluate          # تشغيلٌ يدويّ: «تنبيهات: N إطلاق · N تعافٍ · N حادثة آلية · N إشعار»
```
- افتح `/admin/alerts` وافرز بالشدّة ثم بالمصدر (`AlertEngine::SOURCES`: فشلُ دخول · منع · تغييرُ أدوار · قفلُ طوارئ · أخطاءٌ حرجة · مجدولةٌ متعطّلة).
- تنبيهٌ من `health.scheduler` ⇒ **الكتيّب ١** (المجدولات) هو العلاج، لا التنبيه.
- تنبيهٌ من `security.failed_logins`/`security.denials` ⇒ **الكتيّب ٥** (اشتباهُ تسرّب).

**المعالجة:**
1. **أقرّ** (`ack`) بما رأيتَه فعلاً — الإقرارُ في `alert_instances` وحدَه (لا سطحَ ثانياً)، وهو يُسكت الصفَّ ولا يخفي الشرط.
2. **ارفع للحادثة** ما يستحق استجابةً (زرُّ «افتح حادثة») — يفتح حادثةً ببصمة `alert:<dedup_key>`، فإعادةُ الضغط تُثري القائمةَ ولا تفتح ثانية.
3. **اضبط الضجيج عند مصدره لا بالكتم:** رفعُ عتبة القاعدة أو نافذتها (`window_min`) من سجلّ قواعد التنبيه، أو رفعُ تبريدها (`cooldown_min` للقاعدة، وإلا المفتاحُ العامّ `security.alert_cooldown_min`).
4. **لا تحذف صفوفَ التنبيه** لتُنظّف الشاشة: الحلُّ يقع تلقائياً حين يزول الشرطُ في التقييم التالي.

**التحقق:** بعد `hub:alerts-evaluate` تعود الصفوفُ المعالَجة `resolved`، ونبضةُ «تقييمُ التنبيهات» في مركز التشغيل حديثة (`Health::JOBS` يحرسها).

## 12) فرزُ النتائج الأمنية (`/admin/security/findings`)

**الأعراض:** بطاقةُ الأمن في `/admin/control` تعرض نتائجَ حرجة؛ أو درجةُ الوضعية هبطت بعد لقطةٍ يومية.

**افهم أولاً — النتيجةُ ليست حدثاً:** الحدثُ لحظةٌ وقعت (يُقرأ في `/admin/security/event/{source}/{id}`)، والنتيجةُ **شرطٌ قائمٌ منذ `first_seen_at`**. الفرقُ عمليّ: الحدثُ يُقرأ ويُنسى، والنتيجةُ تبقى حتى يزولَ شرطُها. والشدّةُ **بالرمز** (`SecurityFindings::SEVERITY_BY_CODE`) لا بلون الصفّ.

**التشخيص:**
```bash
php artisan hub:security-snapshot        # يعيد تسوية النتائج مع اللقطة الحيّة ويكتب الدرجة
```

**المعالجة (بالترتيب):**
1. رتّب بالشدّة: `critical` أولاً (بلا تحقّقٍ بخطوتين للمميّزين · كلمةُ مرور المنصِّب الحيّة · سلسلةُ تدقيقٍ مكسورة)، ثم `high`.
2. افتح النتيجةَ واقرأ **دليلَها** (`evidence` — مطموسٌ بـ`Redactor::arr`) و**توصيتَها** (تأتي من `fix`/`url` في فحص الوضعية، لا تُخترع عند العرض).
3. عالج الشرطَ من الشاشة التي يحيل إليها الزرّ — لا من هنا.
4. **الإقرارُ (`ack`) ليس حلّاً**: ينقل الحالةَ إلى «مُقَرٌّ بها» لا «محلولة» — أي «رأيتُه وقرّرتُ العيشَ به الآن»، والشرطُ ما زال قائماً و`last_seen_at` ما زال يتجدّد مع كل لقطة.
5. لا تحذف نتيجةً أبداً: تُغلق تلقائياً حين تُشاهَد **سليمةً** في اللقطة التالية. وفحصٌ سقط بعطلٍ حالتُه *مجهولة* لا *سليمة* — فلا يُغلق شيءٌ لأن فحصَه غاب.

**التحقق:** بعد المعالجة، `hub:security-snapshot` يُغلق النتيجةَ (`resolved`) وترتفع الدرجةُ في `/admin/security`؛ ويختفي بندُها من صفّ `/admin/control` بلا تدخّلٍ يدويّ.

## 13) سلسلةُ تدقيقٍ مكسورة

**الأعراض:** بطاقةُ التدقيق في `/admin/control` تقول «⚠️ عبث»؛ أو نتيجةٌ أمنية بالرمز `audit_chain` (شدّتُها `critical`)؛ أو فشلُ `hub:audit-verify` (وهو **يفتح حادثةً أمنية** تلقائياً).

**هذا أخطرُ ما في الوثيقة:** السلسلةُ هي ما يجعل سجلَّ الأثر دليلاً. كسرُها يعني إمّا تعديلاً مباشراً في القاعدة، أو حذفَ قيود، أو فشلَ ختمٍ في الكود.

**التشخيص:**
```bash
php artisan hub:audit-verify             # الفحصُ الكامل — يكتب صفّاً في audit_verifications
```
ثم `/admin/audit/coverage` (للمالك) يعرض آخرَ ستّ تشغيلاتٍ بعدّاداتها. اقرأ العمودَ الذي كسر:

| العدّاد | ماذا يعني | أوّلُ ما تفعل |
|---|---|---|
| `mismatch_rows` | محتوى القيد لا يطابق بصمتَه | **تعديلٌ مباشر في القاعدة** — تعامل معه حادثةَ أمنٍ لا عطلَ برمجة |
| `unsealed_rows` | قيدٌ كُتب **بلا بصمة** بعد بدء السلسلة | فشلُ ختمٍ في الكود أو كتابةٌ التفّت على `Auditable` — راجع آخرَ نشر |
| رأسُ السلسلة لا يطابق آخرَ قيد | حُذفت قيودٌ من الذيل | استعادةُ نسخةٍ ومقارنة |
| `weak_rows` | مختومٌ ببصمة الجيل الأول (v1) | ليس كسراً: صفوفٌ قديمةٌ صالحة |

**المعالجة:**
1. **لا تُصلح السلسلةَ لتخضرّ الشاشة.** الكسرُ دليل: صوّره (لقطةُ الصفّ في `audit_verifications`، ورقمُ `first_bad_id`) قبل أيّ شيء.
2. افتح حادثةً أمنية واربط بها الدليلَ (`/admin/incidents/{id}/link` بنوع `audit`).
3. اقرأ القيدَ المتأثّر وما حوله: `/admin/audit/{id}` (تحقّقٌ موضعيّ للصفّ) و`/system/trace/{rid}` بمعرّف طلبه إن وُجد.
4. راجع من يملك وصولاً مباشراً للقاعدة، ودوّر اعتمادَه.
5. **لا `migrate:fresh` ولا حذفَ صفوف** — سلسلةُ التدقيق خارج كلّ تقليمٍ عمداً، و`audit.retention_days` **وصفٌ لا مقصّ** (لا كودَ تقليمٍ يقرؤه).

**التحقق:** تشغيلٌ نظيفٌ لـ`hub:audit-verify` بنتيجة `ok`، وصفٌّ جديد في `audit_verifications`، ونتيجةُ `audit_chain` تُغلق في اللقطة التالية. والحادثةُ **لا تُغلق آلياً**: أغلِقها بتقريرٍ (سببٌ جذريّ + خطواتٌ + وقاية).

## 14) استعادةُ إعداداتٍ ذهبت في الاتجاه الخطأ

**الأعراض:** بعد استيراد ملفِّ إعداداتٍ أو «استعادة الافتراضي»، تبدّل سلوكُ النظام: بريدٌ لا يخرج، أو حارسٌ أمنيّ اشتعل/انطفأ، أو تكاملٌ يقول «غيرُ مهيّأ».

**اعرف أولاً ماذا تغيّر ومن أين:**
- `/admin/settings` يعرض لكلّ مفتاح: المخزَّن · الافتراضيّ · **الساري** · ومصدرَه (`default` · `database` · `environment` · `module`). مفتاحٌ مصدرُه `environment` **لا تغيّره الشاشةُ ولا الملفّ** — عالجه في `.env`.
- تاريخُ التغيير في `setting_changes`: كلُّ صفٍّ يقول **من أيّ بابٍ** جاء (`Settings::WRITERS` — شاشة · استيراد · استعادة · طرفية…) ومتى ومَن. والقيمُ السرّية بصمةٌ لا نصّ.
- وسجلُّ التدقيق يحمل الفعلَ: «تعديل إعدادات النظام» أو **«استعادة افتراضي الإعدادات»** (فعلٌ مستقلّ عمداً كي يُفرَّق بينهما).

**المعالجة:**
1. حدّد المفاتيحَ المتغيّرة من `setting_changes` (رتّب بالوقت تنازلياً).
2. أعِد القيمةَ السابقة **من شاشة الإعدادات** — وستمرّ بالمعاينة (`settings.preview`) التي تُريك «من ماذا إلى ماذا» قبل الكتابة، وبتأكيدِ هويةٍ إن كان المفتاح عاليَ الخطورة.
3. **لا تحذف صفَّ الإعداد من القاعدة** لتعيده لافتراضيّه: مفتاحٌ افتراضيُّه «مُشغَّل» يعود مُشغَّلاً بحذفه — وهذا انقلابُ حالةٍ لا استعادة. استعمل زرَّ «استعادة الافتراضي» (يكتب `default` المُعلَن ولا يحذف).
4. مفتاحٌ تملكه شاشةٌ أخرى (صيانة/قفلُ طوارئ/تجميد) **لا يُبدَّل من ملفٍّ ولا من هنا** — بابُه مركزُ التشغيل أو مركزُ الأمان بتأكيدٍ ورسالةٍ وأثر.
5. استيرادٌ ذهب بعيداً: أعد استيرادَ ملفِّ تصديرٍ **أقدم** — الاستيرادُ لا يحذف صفّاً ولا يمسّ سرّاً، فما لم يكن في الملف يبقى كما هو. وإن لم يوجد ملف: `hub:backup` القديم يحمل جدولَ `settings` كاملاً؛ اقرأ منه القيمَ يدوياً **ولا تستعده كاملاً** على الإنتاج (‏`hub:import` استعادةُ قاعدةٍ لا استعادةُ إعدادات — الكتيّب ٨).

**التحقق:** `/admin/settings` يُظهر القيمةَ السارية الصحيحة ومصدرَها `database`؛ صفٌّ جديد في `setting_changes` بمصدر `screen`؛ وقيدُ تدقيقٍ بالفعل الصحيح. ثم اختبر الأثرَ نفسَه (زرُّ اختبار الاتصال، أو محاولةُ دخولٍ للحارس الأمنيّ).

> **قبل أيّ استيرادٍ في المرة القادمة:** صدّر ملفاً من التنصيب الحاليّ (`/admin/settings/export`) واحفظه — فالفرقُ بين ملفّين أسرعُ طريقٍ للرجوع. والتصديرُ لا يحمل سرّاً ولا صفَّ حالةٍ ولا مسارَ ملفٍّ محلّيّ (`docs/CONTROL_PLANE.md` §٨).
