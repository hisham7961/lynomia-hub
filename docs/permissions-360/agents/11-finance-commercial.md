# 11 — الماليّة والتجاريّة

> وكيلُ تدقيقٍ للقراءة فقط (Permissions 360 · المرحلة 0). مصدرُه سيرُ التدقيق `wf_8fdd85b1-7b4`.

## الخلاصة

Audited every finance/commercial surface: action controllers (FinController pay, EntryController journal lines/post, QuoteController + QuoteBuilder, PurchaseController, PayrollController, ContractActionsController, ChangeOrderController, EmployeeCustodyController), read/dashboard controllers (CostController, SalesController, PricingController, ReportController::finance, PurchaseController::scores), the generic ModuleController (index/show/board/export serving fin/entries/accounts2/budgets/costc/recur/banks/quotes/contracts/purchases/changeorders/products/services), the REST V1Controller, QuoteFlow, and the client portal (ClientPortalController + ClientPortalData). Headline: write-side authorization is genuinely strong — every mutating finance route enforces hub_can(module,op) + hub_scope + cross-module target perms (fin.a for invoicing, banks.e for balance movement, projects.e for change-order application) with row locks and step-up on custody reversals. The real gaps are (1) a VERIFIED field_leak: the REST shape() strips only DECLARED module fields, so the undeclared `meta` column serializes project commercial baselines (contract amount, per-line unit_price/line_total, change-order cost_delta) via /api/v1/projects, bypassing field_rules hide on cost/budget/revExp — and projects+fin are in PortalGuard's client allowlist; (2) financial visibility is coarse — module `v` reveals all figures, and separation depends entirely on opt-in per-role field_rules with no dedicated permission; (3) three global flags (exp, approve, monitor) each unlock unrelated finance capability across every module. Client portal isolation (fail-closed hub_client_ids, hand-picked client-safe columns) is correctly built.
