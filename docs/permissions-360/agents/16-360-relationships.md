# 16 — نوافذ 360 وشبكة العلاقات

> وكيلُ تدقيقٍ للقراءة فقط (Permissions 360 · المرحلة 0). مصدرُه سيرُ التدقيق `wf_8fdd85b1-7b4`.

## الخلاصة

Audited the four 360 read models (Employee360/Asset360/Station360 support classes + the Project 360 view path via project_assets), RelationshipProjection + RelationshipExplorerController (graph.explore / graph.expand), the graph blade, related-record counters (hub_related/record_list) and contextual action links. The graph engine is genuinely strong: every node passes hub_read (module v + hub_scope + soft-delete), counts are the filtered hub_read count not raw, edges are emitted only when BOTH endpoints are independently readable, labels honor hub_field_mode(hide), the cap is explicit (capped flag) not a silent truncation, the cache key carries the full reader fingerprint, and guardInternal 404s clients and client-scoped internal readers. Employee360 tabs and Station360 subsections each carry their own per-module hub_can gate, and hub_related enforces hub_can(child,v)+hub_scope. The one real class of defect is symmetric: the Asset-360 'projects' tab and the Project-360 'assets' tab render the counterpart relationship (names + counts) with NO counterpart-module v-gate and NO hub_scope — shown to any internal reader, pulling unscoped names through AssetProjectService::activeForAsset/activeForProject eager-loads. Root/holder/occupant identities are by-design ref fields, not leaks.
