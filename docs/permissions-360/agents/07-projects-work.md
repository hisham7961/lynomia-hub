# 07 — المشاريع ونظام العمل

> وكيلُ تدقيقٍ للقراءة فقط (Permissions 360 · المرحلة 0). مصدرُه سيرُ التدقيق `wf_8fdd85b1-7b4`.

## الخلاصة

Audited the Projects/Work-OS domain: ModuleController (generic engine serving `projects`), Project360 composition (resources/views/modules/custom/projects.blade.php, included by modules/show.blade.php:93), CostController (P&L dashboards), AssetProjectController + AssetProjectApiController (asset assignment), ChangeOrderController, ApprovalService/ApprovalDecisionController, ReportsController + ReportReview (report review), CapacityController lenses, ClientPortalController/ClientPortalData (portal), V1Controller/ReportsApiController/MobileWorkController APIs, and config/hub.php projects/tasks/updates field defs. Single engine confirmed: hub_can(module,op) over role.matrix, hub_field_mode for fields, hub_scope for isolation, hub_monitor/hub_approver flags, PortalGuard for client boundary. Most surfaces are correctly gated (asset-assign requires assets.e+projects.v+scope; change-order apply requires changeorders.e+projects.e; approvals re-check hub_approver+module perm+scope; API shape() honors field-mode; client portal is fail-closed with client-safe columns). HEADLINE DEFECTS: (1) projects.v is a single coarse gate that by default exposes full project profitability (Project360 finance tab) and, separately, the entire team work-log/hours/blockers stream (activity tab) with NO dedicated finance/activity permission — the activity tab bypasses updates.v entirely, though the delivery tab on the same page gates that exact module via hub_related; (2) CostController gates the identical hub_project_pl data by the monitor flag, ignoring the field-mode cost/budget lever that every other surface honors. Distinct project privileges (view ≠ financials ≠ technical ≠ members ≠ asset-assign ≠ activity/hours ≠ archive) are almost entirely non-separable today.

- Feature: proposed projects.fin.view — grant it false and confirm finance tab hidden even when cost/budget field-mode is open; grant true and confirm shown.
- Feature: proposed projects.members.manage/fin.edit/tech.edit — a role with members.manage but not fin.edit PUTs a project with a changed budget and asserts budget is unchanged (write-field authority enforced), while manager_id/members changes persist.
- IDOR: proj-scoped user (scope=proj) requests /costs?p={foreignProjectId}, capacity?p={foreign}, and api/v1/reports/progress/{foreign} — all must 404 (hub_scope/hub_lens).
- Feature: hub_project_health budget-factor renormalization — for a role with budget hidden, health score equals the score computed without the budget factor (no residual budget signal).
