# 17 — الاستيراد والتصدير والجماعيّ والطباعة

> وكيلُ تدقيقٍ للقراءة فقط (Permissions 360 · المرحلة 0). مصدرُه سيرُ التدقيق `wf_8fdd85b1-7b4`.

## الخلاصة

Audited every CSV/PDF/print/download/bulk/import/copy-sensitive egress path (grepped streamDownload/fputcsv/->download/export/bulk/import; read ModuleController, ImportController, ReportsController, SettingController, AttachmentController+AttachmentService, MobileFileController, Quote/ChangeOrder/Esign PDF, Identity/Custody labels, DataRoom). The core generic export path (ModuleController::export + bulk do=export) is well-hardened: a single shared exportBelt() enforces exp-flag + freeze switch (423) + step-up + DATA_EXPORT audit, and streamCsv() equals read scope (hub_scope hard company/project/client isolation + hub_field_mode hide + sec-field masking + CSV formula-injection neutralization + 5000-row cap). ImportController enforces hub_can(a) + full-scope-only + per-field hub_field_mode + company isolation on writes and ref resolution. Attachment single/zip/mobile downloads all funnel through AttachmentService::guardRecord (view + hub_scope->findOrFail, no IDOR). Settings export/import is owner-only + freeze + audit. Headline defect: ReportsController::monthlyExport streams a full-company monthly attendance CSV for all employees while bypassing the ENTIRE export belt — no freeze check, no DATA_EXPORT audit fingerprint, no exp flag, no step-up — the exact 'guard applied at one door, forgotten at another' anti-pattern exportBelt() was written to kill; confirmed untested under freeze. Secondary: the 'exp' flag is a single global toggle with zero per-domain export granularity.
