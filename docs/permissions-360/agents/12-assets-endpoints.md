# 12 — الأصول والمحطّات والنقاط الطرفيّة

> وكيلُ تدقيقٍ للقراءة فقط (Permissions 360 · المرحلة 0). مصدرُه سيرُ التدقيق `wf_8fdd85b1-7b4`.

## الخلاصة

Read all 12 domain controllers (CustodyController, EmployeeCustodyController, StationController, AssetProjectController + API, InventoryController, StockController, EndpointCentreController, EndpointMdmController, EndpointReleaseController, EndpointProtocolController, EndpointEnrollController, AssetLifeController, DigitalAssetsController), the `assets`/`stations`/`endpoints` module defs in config/hub.php, ModuleController generic CRUD gating, RoleController::groupedModules, and the hub_can/hub_monitor helpers. The custody/station/asset-project/inventory/stock write paths are well-guarded (hub_can + hub_scope + hub_company_scope, locked fields, step-up on money/inventory-close, signed protocol for the machine surface). The headline defects are AUTHORITY-BUNDLING, not missing gates: (1) the endpoint fleet is documented monitor-only in EndpointCentreController but is a full ModuleController CRUD module (`endpoints`), reachable via /m/endpoints with a plain matrix `endpoints:v` grant — a second, laxer door to the same device data (view/edit/delete/export) that defeats the stated invariant; (2) device-management authority (issuing apply_policy/refresh commands, minting enrollment tokens) is bound to the coarse RISKY `monitor` analytics flag rather than a dedicated assignable endpoints permission — apply_policy/refresh need only monitor with no step-up; (3) a single `assets:e` op simultaneously grants custody-assignment authority (handover/recover/transfer permits to people), technical lifecycle (status/station), internal specs, AND inventory freeze/scan — none separable. Field-level price/serial hiding, export column filtering, and cross-company IDOR scoping are otherwise correct. One minor gap: station assignment does not scope the assignee user to the reader's company.
