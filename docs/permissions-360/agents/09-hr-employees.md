# 09 — الموارد البشرية والموظفون

> وكيلُ تدقيقٍ للقراءة فقط (Permissions 360 · المرحلة 0). مصدرُه سيرُ التدقيق `wf_8fdd85b1-7b4`.

## الخلاصة

Audited the HR/employee domain: the generic ModuleController (m/{module}) that serves hr/leaves/attend/hrlog/payroll/recruit/skills, the 360 profile (PortalController + Employee360), TeamDirectory/TeamController, StaffController (file↔account linking), PayrollController, EmployeeCustodyController, HireController, the V1 + Mobile REST APIs, and config/hub.php field/module definitions. Headline: the single authorization engine (hub_can per module + hub_field_mode per field) is applied CONSISTENTLY across list columns, show, export, ?q= search, f[]/fl[] filters, sort, and API shape() — a genuinely strong, single-engine design. Attendance/leaves/disciplinary(hrlog)/daily-reports(updates) ARE already separate modules with their own v-gates, so those sensitive sub-surfaces are separable. The real gaps: (1) the 360 'reports' tab is gated only by updates:v yet surfaces raw attendance check-in/out times and presence status, bypassing attend:v; (2) salary/allowances and financial+identity PII (IBAN, civil ID, iqama, passport) have NO positive permission and are separable from hr.v ONLY via opt-out field_rules that default OPEN — an owner must remember to set hide on every role; (3) full employee records (salary/PII, per role visibility) are classed CACHEABLE_INCREMENTAL so they persist to mobile devices; (4) HR export is gated only by the one global RISKY 'exp' flag, no per-module export separation.

## اختبارات مطلوبة

- Employee360::dailyReports — user with updates:v and WITHOUT attend:v must receive rows with time_in/time_out/physical/late nulled (or the reports tab must not expose attendance) for another in-scope employee (proves finding #1 fixed).
- Fresh non-owner role with hr:v and empty field_rules must NOT see salary/allow/iban/civil_id/iqama/passport on GET /m/hr/{id}, GET /m/hr (list), GET /m/hr/export, and GET /api/v1/hr/{id} (proves default-closed after fine-grained keys, finding #2).
- hub_scope isolation: user scoped to company A requesting PortalController::employee, /m/hr/{id}, /api/v1/hr/{id}, and custody-wallet/e/{id} for a company-B employee gets 404 not 200 (IDOR regression guard).
- ?q= search on hr with iqama/passport set to field_rules hide must NOT match by those hidden values (search-oracle guard — currently passes via Searchable trait; lock it).
- Mobile sync payload for module hr must exclude salary/iban/civil_id, or hr must be reclassified non-persisting (finding #3).
- Role holding global exp flag but not the proposed hr.export must be denied m/hr/export and m/hr/bulk do=export while other-module export still works (finding #4).
- Escalation invariant: role with hr:e (no users flag) cannot link/align an employee file to an owner or users-flag account (Staff::mayTouch) and cannot open a system account via StaffController::account.
- Payroll: role with payroll:e but no approver flag cannot approve a run; generate must only pull employees within the actor's hub_scope(hr)+company.
