# 14 — الإعدادات والأمن والإدارة والمطوّر

> وكيلُ تدقيقٍ للقراءة فقط (Permissions 360 · المرحلة 0). مصدرُه سيرُ التدقيق `wf_8fdd85b1-7b4`.

## الخلاصة

Audited every admin/security/dev surface in scope: SettingController, UserController, RoleController, AccessController(/admin/access), AuditController, FeatureController, DataRoomController, IntegrationController, N8nController, WebhookController, InboundHookController, OdooController/OdooConnectionController, SecurityController (full, 1287 lines), OpsController (full, 1045 lines), ErrorCenterController, ControlController, MessagingController, ProfileController tokens, MySecurityController, SystemMapController, SystemTraceController, RemediationController, EndpointEnrollController::mint, StepUpController, and the demo/health routes. Headline: the single engine (hub_can/hub_flag/hub_field_mode/hub_scope + hub_is_owner) is applied cleanly and consistently — every controller calls its gate() in EVERY public method; owner-only centers (settings, roles, features, integrations, ops, error-center, security actions) hard-gate on hub_is_owner; sensitive actions add step-up (hub_require_stepup / _ops_stepup / _credential_stepup); read-only security dashboards open to owner||monitor apply PII masking + company scoping (critic #9); UserController blocks privilege escalation and last-owner lockout; owner bypasses by design. No uncovered route, no UI-hidden-but-reachable bypass, no cross-tenant IDOR, no unscoped export found. The only defects are privilege-granularity / over-broad flag couplings — chiefly the copySec flag granting the SAME full plaintext secret-reveal as secrets, contradicting its narrower presented purpose.

## اختبارات مطلوبة

- copySec-only role (secrets=off) must receive 403 from GET revealSecret for a sec-type field, proving copySec is not a plaintext-reveal path.
- secrets-flag role can create AND revoke data-room share links; a role WITHOUT secrets receives 403 from DataRoomController::store — and (after split) a vault.reveal-only role cannot create public share links.
- Non-owner with users flag cannot: (a) assign the owner role via role_id, (b) edit/delete/2fa-off an owner account, (c) broaden its own company isolation on self-update — each returns 403 (guardEscalation / self-scope tests).
- Last active owner cannot be suspended, deleted, or role-changed away from owner (activeOwners/activeOwnersLocked lockout) even under concurrent delete (row-lock race test).
- FeatureController::toggle on a SYSTEM_INVARIANT capability throws/blocks; and a high-risk setting_key toggle demands step-up.
- Audit index/show filters cannot widen Audit::scopedQuery (company/client/project scoping holds); out-of-scope audit.show returns 404 not 403.
- monitor-flag (non-owner) reader of security.findings/identity/sessions/devices/ips/event sees masked email/IP/name and only company-scoped rows; and CANNOT ack/resolve/freeze/lockdown/revoke (owner-only actions 403).
- Ops migrate/maintenance/clear-cache/outbox-retry and demo reset/off require hub_require_ops_stepup; a fresh-session non-stepped owner is redirected to step-up.
- Admin token revoke (SecurityController) and self token mint/rotate (ProfileController) both honor security.freeze_tokens (423) and credential step-up; self token endpoints only touch where user_id=auth id.
- MDM enroll mint: client account => 404; asset outside caller's company scope => 404; and (after fix) a monitor-only role without the intended mobile/enroll grant is refused.
