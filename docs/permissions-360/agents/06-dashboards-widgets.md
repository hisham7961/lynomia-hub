# 06 — اللوحات والودجات والعدّادات

> وكيلُ تدقيقٍ للقراءة فقط (Permissions 360 · المرحلة 0). مصدرُه سيرُ التدقيق `wf_8fdd85b1-7b4`.

## الخلاصة

Audited DashboardController + WidgetRegistry (10 built-in widgets), CeoController/CeoBoard, PerformanceController, MonitorController, CapacityController, KpiController+KpiCentre, CostController+SalesBoard, AlertCenterController, OversightController, WorkforceController, ControlController+AttentionQueue, and the sidebar attention/inbox badges (Workspaces, CollaborationRail, NotificationController). The single authorization engine (hub_can/hub_flag/hub_scope + hub_org_analytics_guard) is applied consistently and most counts are correctly filtered BEFORE aggregate: the dashboard counts/donut/due/apps/expiry/audits widgets, hub_kpi_metric, SalesBoard, CostController::index, ControlController cards, and the badge counters all pass through hub_can+hub_scope, and shared/role dashboards re-gate every widget at render (BoardController + DashboardController::layoutFor). Owner-only surfaces (CeoController, alerts.ack/incident) and the oversight officer path (role-name + step-up + reason + company/client scope) are sound. Three verified defects remain, all in the analytics tier gated by the coarse monitor flag: (1) the /kpis trend delta/series is an org-wide snapshot leaked to scope-restricted monitor users while the current value is correctly scoped; (2) hub_org_analytics_guard only blocks company/client isolation, not project scope, so a project-scoped user granted monitor reads org-wide revenue/salary/performance aggregates; (3) the /kpis owner dropdown enumerates all active users unscoped. The monitor flag itself is over-broad, bundling company performance, per-employee ratings, cost/profitability, capacity, and the KPI builder under one toggle.

## اختبارات مطلوبة

- Project-scope regression: a user with role.scope='proj' (no companies/clients) + flags.monitor=1 must be 403 (or receive strictly project-scoped data) on /performance, /capacity, /workforce, /service-costs and the Control quality/execution cards — assert hub_org_analytics_guard blocks hub_scoped().
- KPI trend isolation: a company-isolated monitor user on /kpis must not receive an org-wide trend delta/series — seed metric_points with an org-wide snapshot larger than the user's scoped value and assert the rendered trend is null/blank (or the page 403s).
- KPI directory isolation: a company-isolated monitor user without hr.v requesting /kpis must not see user names outside their company in the owner dropdown.
- Widget gate at render: build a shared/role Dashboard containing the kpis and counts widgets as owner, then load it as a non-monitor project-scoped user and assert the kpis widget is dropped and counts show only scoped totals (WidgetRegistry::isVisible + hub_scope enforced regardless of board author).
- Count-before-aggregate: for the dashboard counts/donut widgets and hub_kpi_metric, assert a company-isolated user's returned count equals COUNT over hub_scope()-filtered rows (not the raw table), i.e. scope applied before count()/GROUP BY.
- AlertCenter org-wide baseline: assert alert_instances.company_id stays NULL on fire (AlertEngine) so the owner||monitor alert counts remain genuine org-wide system alerts and never carry per-company data without a scope filter being added.
