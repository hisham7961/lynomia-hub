> وكيلُ تدقيقٍ للقراءة فقط (Permissions 360 · المرحلة 0). مصدرُه سيرُ التدقيق `wf_8fdd85b1-7b4`.

## الخلاصة

Audited the daily-reporting + attendance domain: ReportsController (index/day/review/reviewAct/mine/monthly/monthlyEmployee/monthlyExport/finalize), WorkdayController (checkIn/checkOut/team), WorkforceController, and the read APIs (ReportsApiController, MobileReportsController), against DailyWorkCompliance / MonthlyAttendance / ReportReview / Workday and the helpers (hub_can/hub_scope/hub_company_scope/hub_company_ids/hub_is_client/hub_monitor/hub_org_analytics_guard). The intended scope separation HOLDS on read paths: attend.v reaches only the monthly attendance grid/sheet/export which emit compliance STATUS labels + times + hours (never report done/problems/next text), while daily report CONTENT (reports.day full text, reports.review queue showing done) is gated by hr.v (and updates.e for project-scoped review). Reads are strictly company-isolated via hub_scope (day, monthlyEmployee, index, teamDaily all wrap hub_scope). BUT two write actions drop the strict isolation: (1) reports.finalize gates cross-company access only with hub_company_scope, a display filter that no-ops when no active company is set in session (the DEFAULT state) -> cross-company write of compliance_outcome that feeds payroll; (2) ReportReview::canReview returns true for any hr:e holder with NO company/project scope check, so the review-act POST reaches work_updates the (scoped) queue hides. Export is bundled into the monthly-view op with no separable permission.

## اختبارات مطلوبة

- اختبار يفشل أولاً (F1): مستخدم hr.e معزول على C1 مع session hub.company='' يرسل POST reports/compliance/{attendanceIdOfC2}/finalize -> يجب 404 (حالياً 200 ويُكتب compliance_outcome).
- اختبار (F1): نفس المستخدم بعد اختيار C1 كشركة نشطة ثم POST على صف C2 -> 404 (الإصلاح لا يعتمد على الجلسة).
- اختبار يفشل أولاً (F2): hr.e معزول على C1 يرسل POST reports/review/{workUpdateIdByC2Employee} action=accept -> يجب 403 (حالياً canReview=true).
- اختبار (F2 إثبات إخفاء القائمة): hr.v معزول على C1 يفتح GET reports/review -> لا تظهر بنود C2 (يؤكد أن الثغرة في الفعل لا العرض).
- اختبار فصل النطاق (regression موجب): حامل attend.v فقط (لا hr) يفتح monthly/monthly.export بنجاح لكنه يُردّ 403 على reports.index، reports.day، reports.review، api reports/daily — يثبّت أن attend.v لا يصل محتوى التقرير.
- اختبار (F3): بعد فصل attendance.export، دور يحمل attendance.monthly.view دون attendance.export -> 403 على monthly.export و200 على monthly.
- اختبار عزل التصدير: attend.v معزول على C1 يصدّر -> CSV يحوي موظفي C1 فقط (monthlyEmployees=whereIn(company_id,hub_company_ids)).
- اختبار (F4): موظف يسجّل حضوراً بـproject_id خارج نطاقه -> القيمة تُهمَل/تُرفض بعد الإصلاح.
