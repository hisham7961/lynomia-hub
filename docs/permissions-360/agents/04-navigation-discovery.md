# 04 — التنقّل والاكتشاف (IA/بحث/لوحة أوامر)

> وكيلُ تدقيقٍ للقراءة فقط (Permissions 360 · المرحلة 0). مصدرُه سيرُ التدقيق `wf_8fdd85b1-7b4`.

## الخلاصة

Audited the navigation/IA/discovery layer: app/Support/helpers.php (hub_nav:324, hub_top_links:393, hub_top_groups:519, hub_admin_links:5687, hub_pins/hub_pin_targets:461/470, hub_home_url:547), app/Support/InformationArchitecture.php (guards:58-108, destinationVisible:169, visibleDomains:243, searchDestinations:658, catalogDestinations:697, navigationPayload:719, systemMap:763, breadcrumbs:582), config/hub_ia.php, SearchController (mini/index/destinations/operational/workOs/recents/quickActions), WidgetRegistry (links widget + isVisible), SavedController, WorkspaceController, layouts/app.blade.php admin bar, and the mobile navigation/search endpoints. Headline: the IA is a single-engine "point-don't-duplicate" design that delegates visibility to hub_can / hub_top_links.ok / hub_admin_links.ok / a named-guard map that matches each controller gate almost literally — I verified ~15 guard predicates and ~30 catalog `ok` predicates against their controllers and they mostly match exactly, with no data/count/field leaks in nav. The real defects are visibility-vs-gate DRIFT (a destination shown to more users than the controller admits → dead links, or narrower than the controller → hidden-but-reachable) and one cross-surface inconsistency where the administration-domain wrapper guard is stricter than the individual admin centers it now contains, hiding monitor/mobile-admin centers from the gear bar and system-map while unified search still surfaces them.

## اختبارات مطلوبة

- Nav/gate parity test: for every hub_top_links entry, assert its 'ok' predicate equals its route controller's gate for a matrix of roles (owner, monitor-only, mobile-only, scope-isolated monitor, single-module viewers) — catches the analytics-scope and identity drifts automatically.
- admin_bar consistency test: a user with ONLY the monitor flag (and separately ONLY the mobile flag) must see control/alerts (resp. mobileplatform) in ALL of: gear bar (hub_admin_links filtered), IA systemMap administration domain, IA navigationPayload, and SearchController::destinations — assert the same set across surfaces.
- WidgetRegistry 'links' widget: assert the inboxdocs tile is absent for a user with neither inboxdocs.v nor files.v, and present when either is held (mirror InboxDocController@gate).
- Scope-isolated monitor: assert capacity/recs/impact/appq/costs/svccosts/kpis/digital.assets are absent from hub_top_links(), searchDestinations, and systemMap when hub_company_ids()!==null or hub_client_ids()!==null (mirror hub_org_analytics_guard).
- identity.center discovery: a products.v-only (no assets.v) user must see the identity center in hub_top_links/pins/search, and reaching the route must not 403.
- Negative visibility (no-leak) regression: a user lacking a module must never see that module's label/center name in hub_nav, hub_top_links, catalogDestinations, searchDestinations, navigationPayload, breadcrumbs, or the dashboard counts/expiry/audits widgets.
- New fine-grained keys (updates.review, attend.export, projects.fin.view): once added, assert each has its own IA destination whose visibility follows the new key, and that the legacy key no longer implies the sub-surface (updates.e no longer grants review center; attend.v no longer grants export).
