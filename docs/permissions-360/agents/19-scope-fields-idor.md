# 19 — النطاق والحقول وIDOR

> وكيلُ تدقيقٍ للقراءة فقط (Permissions 360 · المرحلة 0). مصدرُه سيرُ التدقيق `wf_8fdd85b1-7b4`.

## الخلاصة

Audited the scope/IDOR/field engine (hub_scope, hub_company_ids, hub_client_ids, hub_field_mode, hub_read, hub_ref_options_scoped, hub_related, findScoped, AttachmentService::guardRecord, CommentService::guardTarget, ClientPortalData, RelationshipProjection, V1Controller::shape) and its application across the generic ModuleController, the REST/mobile API controllers, file/attachment serving, comments/DM, client portal, esign, endpoint MDM, search, cost/KPI dashboards. Headline: the isolation engine is mature and correctly enforced almost everywhere — findScoped applies hub_scope before findOrFail, field-mode 'hide' is dropped from serialization/search/sort/filter/board/export, ref-option pickers are scope-filtered, attachments/comments/portal all re-derive authority from the parent record with hub_scope, and the endpoint protocol binds every query to the signed device_id. Cross-company/project/client IDOR and forged-ID acceptance were NOT found in the reviewed paths. The one verified leak is a derived-salary exposure on the cost dashboard (hub_hourly_rates) that bypasses hr field-mode/permission; the rest are fine-grained-separation gaps rather than active breaches (single org-wide flags gating export, secret-reveal, and project financials for all modules at once).

## اختبارات مطلوبة

- Isolation IDOR sweep: for a user isolated to company A (or client A, or scope=proj), assert GET/PUT/DELETE of a company-B record via m.show, /api/v1/{module}/{id}, /api/mobile/v1/{module}/{id}, metrics ingest, acks, attachments download/preview/zip(id), comments store, esign request, endpoints issue — every one returns 404 (not 403, not 200).
- Field-mode serialization: role with field_rules{hr:{salary:hide}} must not receive 'salary' in api/v1 shape(), mobile show, CSV export header/rows, kanban board card, search matches, or sort — assert the key/column is absent and that sorting/filtering by it is refused.
- hub_hourly_rates leak: a user with the monitor flag but WITHOUT hr:v (and one with hr.salary hidden) opens CostController::index — assert the rendered team-average and the per-user rate map are absent/blocked; assert cost:rates cache is not shared across company-isolated viewers.
- Read-only/locked field immutability: POST/PATCH with a crafted payload setting a 'locked' field (e.g. custody action, approval status) or a field-mode 'ro' field must not mutate it (fill() skip), on web AND api.
- Picker scope: hub_ref_options_scoped and every dropdown/autocomplete (refOptions, esign LINKABLE lists, DM colleague picker, client pickers) return only in-scope ids for an isolated user — assert a foreign company/client/project id is absent.
- Client→internal boundary: a client account calling any internal /api/v1/{module} outside PortalGuard::MODULE_ALLOW gets 404; ClientPortalData *Detail with a foreign record id gets 404; conversationMessages never returns internal=true rows.
- Count/aggregate scope: KPI values (hub_kpi_metric), related-record counts (hub_related), and dashboard tallies computed for a company-isolated user reflect only in-scope rows (assert against a seeded cross-company fixture).
