# 01 — نواة التوثيق

> وكيلُ تدقيقٍ للقراءة فقط (Permissions 360 · المرحلة 0). مصدرُه سيرُ التدقيق `wf_8fdd85b1-7b4`.

## الخلاصة

Audited the single authorization engine end-to-end: app/Support/helpers.php (hub_can/hub_flag/hub_field_mode/hub_visible_fields/hub_scope/hub_company_ids/hub_client_ids/hub_scoped/hub_is_client/hub_is_owner/hub_monitor/hub_exporter/hub_approver/hub_secrets/hub_copy_secrets/hub_require_stepup), app/Models/Role.php, app/Models/User.php (isOwner/isClientAccount/can2/flag/visibleProjectIds), app/Http/Controllers/Web/RoleController.php (FLAGS/RISKY_FLAGS/ops/data()/fromTemplate/step-up), app/Support/PermissionInspector.php, config/hub.php (86 module entries), config/hub_roles.php templates, plus the consumers UserController/AccessController/ModuleController export belt. HEADLINE: the spine is a single, coherent, permission-based engine with NO authorization-by-role-name anywhere and strong owner-only invariants (last-owner protection, guardEscalation, owner-role never form-settable). CONFIRMED: hub_can (helpers.php:295) and User::can2 (User.php:79-80) both read matrix[module][op] for ANY op string, so fine-grained (module,action) keys ARE representable at READ time — but ZERO are used today and the entire WRITE/EDIT/INSPECT surface is hard-wired to v/a/e/d only, so a named op key cannot be created via the Roles UI and is SILENTLY WIPED on the next role save. The real live weaknesses are coarse global flags: one `exp` flag = export of every viewable module; one `monitor` flag = ~15 analytics dashboards + individual performance data + digital-assets vault; one `approve` flag = deciding payroll AND purchases AND every approval domain. hub_scope also fails OPEN for any module lacking a company/client/project column. Owner (role.is_owner) bypasses hub_can, hub_flag, hub_field_mode, and returns null (unscoped) from hub_company_ids/hub_client_ids by design.

## اختبارات مطلوبة

- Engine supports named ops (positive): a role with matrix['hr']['salary.view']=1 ⇒ hub_can($u,'hr','salary.view') is true and hub_can($u,'hr','x')=false — proves fine-grained keys work at read time.
- Named-op survives a Roles save (currently FAILS): seed a role with a named op key, POST an unrelated edit through RoleController::update with matrix_submitted, assert the named op key is NOT wiped — will fail until data() preserves unknown ops.
- PermissionInspector surfaces named ops: after adding a key to OPS, assert moduleMatrix/explain report it for /admin/access; guards owner blind-spot.
- Isolation fail-open (write-first, must fail then fix): a company-isolated user querying a module WITHOUT company_id must not see other companies' rows — currently returns unscoped rows.
- Per-module export: a role with export on module A but not module B (or exp fallback) is 403 on B's CSV/bulk export and 200 on A's; assert hidden/sec fields still stripped.
- Step-up on role CREATE: creating a role with a RISKY flag from a non-fresh session returns the step-up 428/redirect (mirror of update()).
- Owner-role invariant: RoleController::store/update/data can never persist is_owner=true, and UserController::guardEscalation blocks a non-owner (users flag holder) from assigning an owner role or editing an owner account.
- Last-owner lock: suspending, deleting, or role-swapping the final active owner is refused (UserController activeOwners guards).
- Field-mode enforcement is honored by every serializer that emits a hidden field (per-endpoint): assert a 'hide' field never appears in list/CSV/API JSON for the restricted role.
