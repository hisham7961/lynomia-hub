# 20 — المطابقة والتغطية والشخصيّات

> وكيلُ تدقيقٍ للقراءة فقط (Permissions 360 · المرحلة 0). مصدرُه سيرُ التدقيق `wf_8fdd85b1-7b4`.

## الخلاصة

Cross-compared all 609 routes against controllers, hub_top_links/hub_admin_links/InformationArchitecture, PortalGuard/MobilePortalGuard middleware, the api/mobile engines, WidgetRegistry, RoleController editor, and tests/Feature. Headline: the single engine (hub_can matrix + 8 role flags + hub_scope + PortalGuard client boundary) covers nearly every surface — the generic web CRUD (ModuleController), api/v1 (V1Controller) and mobile (MobileResourceController) engines all gate hub_can+hub_scope+client-boundary; admin centers gate is_owner/flags; analytics dashboards gate hub_monitor; cross-entity readers (graph/trace/journey) re-gate every node via hub_read; money/custody mutations gate hub_can; approvals gate hub_approver+module-op+scope; notifications/mysecurity are self-scoped. The reconciliation GAPS (master list for the CI gate): (1) exactly one raw role-NAME authorization — OversightController keys access off role->name matching a free-text setting, invisible to RoleController/PermissionInspector; (2) a fine-grained matrix key custody:approve is CONSUMED (permit/settlement/reversal) but is UNGRANTABLE by the role editor and is silently wiped on every matrix save because RoleController only renders/rebuilds v/a/e/d; (3) reports/monthly/export streams attendance CSV bypassing the exp flag + export belt (freeze/stepup/audit) that ModuleController::export enforces; (4) two over-broad flags — global exp (exports every viewable module incl HR/fin) and monitor (unlocks ~12 unrelated analytics/centers incl digital-assets, costs, sales). No unauthenticated human route, no route reachable past PortalGuard for clients, and no unclassifiable mutation route were found beyond these.

## اختبارات مطلوبة

- Feature: a non-owner role whose name equals setting('collab.oversight_role') passes isOversightOfficer while an equally-privileged role with a different name is 404'd — pin the raw-role behavior, then after migration assert access follows the collab.oversight matrix key and that renaming the role no longer changes access.
- Feature: owner sets custody:approve on a role via the editor and it PERSISTS across an unrelated matrix save (name change); today assert it is absent from the editor and is wiped — regression guard for RoleController::data() dropping non-vaed ops.
- Feature: a user with custody:e but not custody:approve gets 403 on custody.wallet.settlement/reverse and custody.permit, while a custody:approve holder succeeds — proves the fine-grained key is enforced and separable.
- Feature: a user with attend:v (or hr:v) but WITHOUT the exp flag is 403 on reports/monthly/export; and with security.freeze_exports=1 even an exp holder is 423 — closes the monthlyExport export-belt bypass.
- Feature: parity test asserting every bulk CSV/data-export route runs through hub_exporter()+freeze+stepup+audit (enumerate export routes: m.export, reports.monthly.export, settings.export) so no future export skips the belt.
- Coverage CI gate: enumerate Route::getRoutes() for web+api, and for every non-public route assert the target controller action reaches an authorization primitive (hub_can/hub_flag/hub_is_owner/hub_monitor/PortalGuard/participation) — fail on any human/mutation route with no gate story (would have flagged monthlyExport).
- Coverage CI gate: assert every op used in any hub_can(...) 3rd argument across the codebase is representable in RoleController ($ops ∪ per-module extra-ops), so a consumed permission key can never be ungrantable (would have flagged custody:approve).
- Feature: over-broad flag guard — a monitor-flag holder is denied digital-assets/costs once monitor is split (monitor.ops vs monitor.finance / dassets.view), pinning the intended separation.
