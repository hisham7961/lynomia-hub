# تدقيق القدرات المخفيّة على مستوى النظام (05)

> المدخل: `FeatureRegistry` (١٣٤ قدرة) + `InformationArchitecture` + كتالوجاتُ التنقّل + المسارات الحقيقيّة.
> الغاية: `ENABLED + USER_FACING + NO_DISCOVERY_PATH = 0`.

## الطريقة (آليّةٌ لا نثريّة)

`DiscoverabilityAuditTest` يمرّ على كلِّ قدرةٍ `ENABLED`، ولكلِّ `web_route` فيها:

1. **يوجد فعلاً** (`Route::has`) — لا نافذةَ وهم.
2. **يُصنَّف في IA** (`routeLocation`) في نطاقٍ معروف — لا «غيرُ مصنَّف» (يتيم).

وكذلك: كلُّ روابطِ `hub_top_links` و`hub_admin_links` توجد (صفرُ روابطَ ميّتة).

## ما كُشِف وأُصلِح

| العيب | الأثر | الإصلاح |
|---|---|---|
| **DEFECT A** — مركزُ التواصلِ خارجَ الشريط | يُبلَغ بالبحثِ وحده | `collab` في `hub_top_links` + إعادةُ تصنيفِ IA إلى center |
| **DEFECT B** — منتقي مشاركين غامض | لبسُ التحديد/الإجبار | منتقٍ صالحٌ (غيرُ محدَّدٍ ابتداءً، بحث، رقائق، عدّ) |
| `workos.global_search` → `search.index` غيرُ موجود | مسارُ قدرةٍ ميّت | صُحِّح إلى `search`/`search.mini` |
