# الأداء (09)

المنهجيّة: تحليلٌ بنيويّ (لا مقاييسَ مختلَقة).

- **قسمُ الأصول:** استعلامان محدودان — `activeForProject` (with('asset:…') · limit 200) واستعلامُ مرشّحين واحد (`whereNotIn` + limit 200). لا N+1 (eager load للأصل).
- **قسمُ المشاريع (الأصل):** `activeForAsset` + `historyForAsset` + مرشّحون — كلٌّ محدودٌ ومرتّبٌ حتميّاً (`assigned_at,id`).
- **الفهارس:** `(project_id,active_flag,id)` · `(asset_id,active_flag,id)` · `company_id` — قراءاتُ النشط/التاريخ مفهرسة (§45).
- **المستكشف:** حافّةُ التخصيصِ محدودةٌ بسقفِ العقد (`limit($maxNodes)`)، لا استعلامَ لكلِّ أصلٍ في حلقة.
- **المشروع 360:** يبقى محدوداً — القرّاءُ القائمون مخبّأون، والأبناءُ عبر `record_list` (معايناتٌ + «عرض الكل»)؛ لا تحميلَ لكلِّ مهمّةٍ/ملفٍّ/سجلِّ تدقيق.
