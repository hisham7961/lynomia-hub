# ROOT_CAUSE — «حضور بدون تقرير» رغم تقديم التقرير

## العيبُ المرصود

موظفٌ (1) سجّل حضوره، (2) سجّل انصرافه، (3) قدّم تقريره اليوميّ — فيُصنَّف يومُه
**«حاضر — بلا تقرير»** خطأً.

## المسارُ الدقيق (مُثبَتٌ من الكود)

`Workday::evaluate()` (`app/Support/Workday.php:147-165`) هو محرّكُ تصنيفِ اليوم:

```php
if ((string) setting('work.report_required', '1') === '1' && $user) {
    $has = DB::table('work_updates')->whereNull('deleted_at')
        ->where('created_by', $user->id)          // ✅ User.id (لا emp_id) — صحيح
        ->whereDate('work_date', $row->date)
        ->exists();
    if (! $has) return self::NO_REPORT;            // ← يطمس الحالةَ الفيزيائيّة
}
```

**المُنادي الوحيد في كامل التطبيق:** `checkOut()` (`Workday.php:127`:
`$row->status = self::evaluate($row, $user);`)، ويُخزَّن الناتجُ مرّةً واحدة (`$row->save()`
سطر 131). لا `checkIn` ولا المجدول ولا **مسارُ تقديمِ التقرير** يُعيدون التقييم.

## الجذر (ثلاثةُ عيوبٍ متضافرة — كلُّها CONFIRMED)

1. **الحالةُ تُحسَب مرّةً عند الانصراف ثمّ لا تُعاد أبداً.** في السيناريو المُبلَّغ يُقدَّم التقريرُ
   **بعد** الانصراف؛ فعند الانصراف لا تقريرَ بعد ⇒ `NO_REPORT` تُخزَّن، ثمّ إنشاءُ `work_update`
   لاحقاً لا يُعيد تقييمَ الحضور. مسارُ الإنشاء (`ModuleController.php:275-278` للوحدة `updates`
   → `work_updates`) وخطّافاتُ الموديل (`WorkUpdate.php:42-95`) تمسّ `tasks.act_h` والتقدّمَ فقط،
   **لا تمسّ الحضور**. فتبقى `attendance.status = NO_REPORT` أبداً.
   - الاختبارُ القائم `WorkforceTest.php:98-123` يكتب التقريرَ **قبل** الانصراف دائماً — فالترتيبُ
     الإنتاجيّ (تقريرٌ بعد الانصراف) غيرُ مُختبَر.

2. **`evaluate()` يطمس الحقيقةَ الفيزيائيّة.** `if (! $has) return self::NO_REPORT;` يُلغي
   `$current` (LATE/REMOTE/FIELD/PRESENT المحسوبةَ سطرَي 153-154). فمتأخرٌ أو ميدانيٌّ بلا تقريرٍ
   يُخزَّن «حاضر — بلا تقرير» لا «متأخر»/«عمل ميداني». **الحضورُ الفيزيائيُّ والامتثالُ التقريريّ
   مدموجان في عمودِ `status` واحد، والامتثالُ يغلب** — وهذا يخالف مبدأ فصلِ الحقائق (§6).

3. **لا مهلةَ (deadline/grace) للتقرير — تصنيفٌ مبكّر.** `NO_REPORT` تُحسَم لحظةَ الانصراف من
   `exists()` آنيّاً؛ لا نافذةَ نهايةِ يومٍ ولا مهلة. `work.report_required` مفتاحٌ on/off بحت
   (`hub_settings.php:634-639`)؛ `work.late_grace` (افتراض 15) للتأخّرِ في الحضور لا للتقرير؛
   والكنسُ `close()` يتخطّى الصفوفَ الموجودةَ (`Workday.php:197`).

## ما ليس السبب (فُحِص وأُبعِد)

- **تطابقُ الهُويّة (§3):** RULED OUT. كلُّ مواضعِ «has report» تقارن `work_updates.created_by =
  User.id` وتَجسُر إلى الموظف عبر `Employee.user_id` (`Employee.php:80-83`, `Workday.php:158/234/247/283`).
  لا موضعَ يقارن `attendance.emp_id` بـ`created_by`. (الاختبارُ §108 سيُثبّت هذا: emp_id ≠ user_id.)
- **`work_date` من `created_at`:** RULED OUT. يُضبَط صراحةً من حقلِ `workDate` أو يُملأ
  `now()->toDateString()` في خطّافِ الحفظ (`WorkUpdate.php:46`) — لا من `created_at`.
- **المنطقة الزمنيّة:** لا عيبَ نشط. `APP_TIMEZONE=Asia/Kuwait` بلا DST؛ `attendance.date` و
  `work_updates.work_date` كلاهما من `now()->toDateString()` بنفسِ الأساس المحلّيّ. (ملاحظةٌ بنيويّة:
  `now()->toDateString()` متناثرٌ بلا مُحلِّلٍ مركزيّ — سيُعالَج بمُحلِّلِ تاريخِ عملٍ واحد.)

## الإصلاح (تصميم)

1. **فصلُ الحقائق:** لا يطمس التصنيفُ الحالةَ الفيزيائيّة. الحضورُ الفيزيائيُّ (حاضر/متأخر/ميداني/
   عن بعد) يبقى في `status`؛ والامتثالُ التقريريُّ والحالةُ المحتسَبةُ يُشتقّان في مُحلِّلٍ مركزيّ
   (`DailyWorkCompliance`) أو يُخزَّنان في حقولٍ إضافيّةٍ مستقلّة — لا في `status`.
2. **إعادةُ تقييمٍ لحظيّة:** عند تقديم/تعديل تقريرٍ (`work_update`)، وعند الانصراف، وعند قبولِ
   تقريرٍ متأخّر — يُعاد تقييمُ يومِ العمل عبر المُحلِّل. المجدولُ شبكةُ أمان.
3. **مهلةٌ وحالات:** إعداداتٌ للمهلة/الحدّ (`attendance.report_*`)، وحالاتٌ قانونيّةٌ متمايزة
   (report_pending قبل المهلة، present_without_report بعدها، absent_due_to_missing_report كسياسة).

## اختبارُ الانحدار (يفشل أولاً)

موظفٌ E ← مستخدمٌ U حيث **E.id ≠ U.id**؛ حضورٌ (emp_id=E.id، دخولٌ وخروج، تاريخ=D)؛ ثمّ
`work_update` (created_by=U.id، work_date=D، محتوىً صالح) **بعد** الانصراف. المتوقَّع:
`hasSubmittedReport = true` والحالةُ الفعّالة «حاضر/ممتثل» لا `present_without_report`. يفشل قبل
الإصلاح (الحالةُ عالقةٌ NO_REPORT) ويمرّ بعده.
