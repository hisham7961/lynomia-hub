# المثبِّتات (MSI/PKG) + التوقيعُ الصادق + تقسيةُ الهويّة/الأوامر/الخصوصيّة (05)

> **مسارُ التصحيح §4/§6/§12/§13.** الحدُّ (C15): **لا توقيعَ زائفٌ ولا تنفيذَ عامّ
> ولا مادّةٌ خاصّةٌ تغادر الجهاز.** المثبِّتُ راحةُ نشرٍ لا سلطةُ ثقة — سلطةُ الثقة
> SHA-256 المنشورة (يتحقّق منها `update.Apply` قبل أيّ تبديل).

## هندسةُ المثبِّتات (§6)

`agent/packaging/` — سقالةُ التغليف والتوزيع:

| الملف | الدور |
|---|---|
| `signing-status.sh` | تقريرُ حالةِ التوقيع الثلاثيّ الصادق (مصدرُ الحقيقة لـCI) |
| `windows/lynomia-agent.wxs` | بيانُ WiX: تثبيتُ الوكيل خدمةً (`run`) — غيرُ موقَّع |
| `windows/build-msi.sh` | بناءُ MSI + توقيعُ Authenticode صادق (NOT_CONFIGURED) |
| `macos/lynomia-agent.plist` | launchd للوكيل |
| `macos/scripts/postinstall` | تسجيلُ الخدمة بعد التثبيت |
| `macos/build-pkg.sh` | بناءُ PKG + Developer ID + notarization صادق (NOT_CONFIGURED) |

سكربتا البناء **يتحقّقان من الأدوات** (WiX/pkgbuild) ويخرجان بلطفٍ (0) حيث لا
تتوفّر — فيمرّان على منصّةِ CI (ubuntu) دون تمثيلٍ ولا فشلٍ زائف، ويبنيان فعلاً على
مضيفَي Windows/macOS.

## قنواتُ التوقيع الثلاث — الحالةُ الصادقة (§6)

| القناة | السرّ | الحالة |
|---|---|---|
| Windows Authenticode | `WINDOWS_CODESIGN_PFX` | **NOT_CONFIGURED** |
| macOS Developer ID | `APPLE_DEVELOPER_ID_P12` | **NOT_CONFIGURED** |
| macOS notarization | `APPLE_NOTARY_KEY` | **NOT_CONFIGURED** |

`signing-status.sh` (يستدعيه CI في وظيفة الوكيل) يُعلن NOT_CONFIGURED حين تغيب
الأسرار — **ولا يطبع «signed»/«notarized» أبداً** بلا شهادةٍ حاضرةٍ وتحقّقٍ فعليّ.
متى ضُبطت الأسرارُ يُوصَل خطُّ التوقيع، ثم تُقرّ حالةُ الإصدار عبر البابَين الشرعيّين
في `EndpointRelease` (`attestVerifiedSignature`/`attestVerifiedNotarization`).

## تقسيةُ الهويّة (§4)

- **العقدُ P-256 حصراً:** التسجيلُ يرفض RSA/P-384/نصّاً مهملاً (`Es256::isP256PublicKey`).
- **المفتاحُ الخاصُّ لا يغادر الجهاز:** الوكيلُ يولّده محليّاً ويخزّنه `key.pem` بصلاحيات
  `0600` (المجلد `0700`)، ولا يرسله قط. والخادمُ **يمسح حمولةَ التسجيل بحثاً عن
  «PRIVATE KEY»** بأيّ حقلٍ كانت ويرفضها ٤٢٢ — لا يخزّن إلا العامَّ وبصمتَه.

## تقسيةُ الأوامر (§12)

القائمةُ المغلقةُ **خمسةٌ لا سادسَ**: `refresh_inventory`/`refresh_posture`/
`apply_policy`/`isolate`/`lock`. أيُّ نوعٍ آخر (shell/powershell/exec/eval/bash/
applescript/plugin/url/…) يُرَدّ ٤٢٢ قبل أيّ أثر — **لا مسارَ تنفيذٍ عامّ في النظام**.
والخطيران (isolate/lock) خلف تصعيدِ هويةٍ + سببٍ إلزاميّ + تدقيق.

## تقسيةُ الخصوصيّة (§13)

`EndpointPrivacy::FORBIDDEN` قائمةٌ غنيّةٌ تغطّي الفئاتِ السبع (لوحةُ مفاتيح/شاشة/
حافظة/تصفّح/محتوى ملفات/كاميرا وميكروفون/التقاطُ شبكة). كلُّ حقلِ مراقبةٍ في أيّ
حمولةٍ من الجهاز (نبضة/حدث/نتيجةُ أمر/معاملاتُ أمر) يُرَدّ ٤٢٢ **خادميّاً بالعمق**
(المفاتيحُ تُفحَص لا القيَم) ولا يُخزَّن منه حرف. وحرّاسُ مصدرِ الوكيل يمنعون
shell/keylog/screenshot/clipboard/packet-capture من الوجود أصلاً.

## الاختبار

- **إثباتٌ لا ادّعاء:** `EndpointHardeningTest` (§4/§12/§13): P-256 حصراً + رفضُ المادة
  الخاصّة، والقائمةُ المغلقةُ الخمسيّة ضدّ ١٤ نوعاً عدائيّاً، وكاملُ قائمة الحظر تُرَدّ.
- الوكيل: `guardrails` (لا shell/جامعات مراقبة/مسح)، `identity` (صلاحياتُ 0600).
- CI: `signing-status.sh` يُعلن الحالةَ الصادقة، وسكربتا البناء يمرّان بلطف.
