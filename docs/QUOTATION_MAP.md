# خريطة نظام عروض المشاريع (Quotation → Project)

> ناتجُ التدقيق الثلاثي الإلزامي قبل أول سطر — v2.374.0+.
> القاعدة الحاكمة: **نوسّع القائم لا نبني ثانياً؛ العرض جسرٌ يشير للكيانات القانونية لا ينسخها.**

## القرار الأول: نوسّع وحدة `quotes` القائمة (لا نبني نظاماً ثانياً)

يوجد أصلاً في الـHub (لا في الجزيرة `quoteflow.html`):
- وحدة `quotes` كاملة (نموذج/هجرة/تعريف/متحكم مخصص `QuoteController`).
- **تحويلٌ قائم**: `toContract()` و`toInvoice()` — معاملاتيّ، مقفول الصف، idempotent عبر `meta['contract_id']`/`meta['invoice_id']`. **هذا قالبُ تحويل العرض حرفياً.**
- خطُّ المبيعات = وحدة `clients` بحقل `stage` (فيه مرحلة «عرض سعر»).
- أحداثٌ دلالية `quote.accepted/rejected` **معلَّنةٌ لكنها لا تُطلَق** (setStatus يتجاوز FlowRunner) — عيبٌ نصلحه.
- **mPDF مثبَّت** (`mpdf/mpdf ^8.3`) وملفوفٌ في `DocRenderer::pdf($html,$title)` بدعم RTL — فالـPDF الاحترافي ممكنٌ خادمياً.
- **eSign غنيّ**: يُعاد استخدامه لقبول العميل (رمز تحقق/OTP/IP/جهاز/QR/تجزئة/سلسلة أدلّة).
- **خصوصية مالية محلولة**: `hub_field_mode` يُخفي إجمالي العرض وبنوده اليوم — نمدّده للتكلفة والهامش.
- **الأرشفة**: `Attachment::create` (نمط `archiveSignedCopy`) يحفظ PDF على سجل العرض.

## ما ينقص ويُبنى (كلٌّ بنمطٍ مُجرَّبٍ في المستودع)

| الحاجة | القرار | النمط المُقلَّد |
|---|---|---|
| بنود مهيكلة (خدمة/مرحلة/تسليم بكمية وسعر وخصم) | جدول `quote_lines` يشير لـservices/products | ref + hub_ref_options_scoped |
| احتساب الإجماليات | خادمياً من البنود (لا يدويّاً) | `Items::parse` sum + decimal:3 |
| ترقيم فريد للعرض | `Quote::nextDocNo` + إعادة محاولة 23000 | `Contract::save()` حرفياً |
| مراحل ومدفوعات | مراحل = بنودٌ بنوع «مرحلة»؛ جدولُ مدفوعات `quote_milestones` | plan_items type + جدول جديد |
| ربحية داخلية | حقول cost/margin مخفيّة عن العميل | `hub_field_mode` = hide |
| إطلاق الأحداث | `FlowRunner::fire('status','quotes',$q,$status)` في setStatus + `converted` في التحويل | `FinController:102` |
| قبول العميل الآمن | إضافة `quotes` لـ`LINKABLE` في eSign + فرع `completeLinked` يقلب الحالة «مقبول» | فروع approvals/policies |
| اعتماد بعتبات (خصم/مبلغ) | `ContractApprovals::spawn` المعتمِدُ بالقيمة، موجَّهاً للعروض | القائم للعقود |
| **تحويل عرض←ارتباط←مشروع** | متحكم يقلّد `toContract` + نمط نسخ الأعمدة، بمعاملة وقفل، يكتب `meta['engagement_id']/['project_id']` | `spawnRenewal` |

## خريطة التحويل (عرض مقبول ← مشروع)

```
عرض مقبول (status=مقبول)
  → [معاملة + قفل صف + فحص meta لمنع التكرار]
  → إنشاء/اختيار ارتباط (Engagement: client_id, revenue=total, billing, scope, currency, contract_id?)
  → إنشاء مشروع خارجي (Project: client_id + engagement_id → تُضيء الربحية والتقدّم القائمين)
  → نقل البنود ذات النوع «مرحلة» إلى plan_items (type=مرحلة) على المشروع  ← تتبّع للعرض في meta
  → نقل جدول المدفوعات (اختياري) إلى فواتير مرحلية أو يبقى مرجعاً
  → خطّ أساس تجاري: لقطةٌ للعرض المقبول (بنوده ومبلغه) في project.meta.baseline
  → ربط: quote.meta[engagement_id/project_id] + project.engagement_id/client_id
  → FlowRunner::fire('converted','quotes',$q) → أحداث onboarding
```

**مصادر الحقيقة (لا ازدواج):** العميل←clients · الفرصة←clients.stage · العرض←quotes · العقد←contracts · الارتباط←engagements · المشروع←projects · الفاتورة←fin. العرضُ **يشير** لها.

## قيود صريحة
- **لا محرك تحويل عملات في الـHub** (متعمَّد) — العملة نصٌّ مُوسَم، المبالغ `decimal(16,3)`. لا نُدخل FX.
- **لا يظهر للعميل**: تكلفة الموظف، الساعة الداخلية، الهامش، ملاحظات الربح — تُفرض خادمياً بـ`hub_field_mode=hide` وعرضٍ يُسقط المخفيّ.
- **لا حذفٌ للتاريخ التجاري**: العروض المُصدَرة تُؤرشَف/تُلغى لا تُحذف.
- **منع تحويلٍ مكرّر**: `meta['project_id']` + قفل الصف.
