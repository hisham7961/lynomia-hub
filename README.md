**نظام إدارة أعمال عربي موحّد** — مشروع Laravel واحد قياسي: **MySQL + Blade + Eloquent** — بلا Docker، بلا أدوات بناء، جاهز للرفع على أي استضافة PHP عادية.

- ٦٩ وحدة أعمال كاملة (شركات، مشاريع، مهام، مالية، عقود، موارد بشرية، مخزون، خزنة أسرار…) تُدار كلها من سجل مركزي واحد `config/hub.php`
- إدارة مستخدمين وأدوار بمصفوفة صلاحيات (عرض/إضافة/تعديل/حذف لكل وحدة)
- سجل تدقيق كامل + إصدارات لكل سجل + سلة محذوفات واستعادة + بحث وفلاتر وترقيم
- واجهة عربية RTL خفيفة بلا أي JavaScript framework


## ٤) استضافة مشتركة (cPanel وأشباهه)

1. ارفع المشروع كاملاً (مثلاً إلى `~/lynomia-hub`) — **خارج** `public_html` إن أمكن.
2. وجّه الدومين/الساب-دومين بحيث يكون **Document Root = `lynomia-hub/public`**.
   - إن لم تستطع تغيير الجذر: انقل محتويات `public/` إلى `public_html/` وعدّل في `index.php` مساري `../vendor/autoload.php` و`../bootstrap/app.php` ليشيرا لمجلد المشروع.
3. أنشئ قاعدة MySQL ومستخدماً من لوحة الاستضافة وضعهما في `.env`.
4. من Terminal في لوحة الاستضافة (أو SSH):
   ```bash
   cd ~/lynomia-hub && composer install --no-dev && composer run setup
   ```
5. ملف `public/.htaccess` مضمّن — أباتشي يعمل مباشرة.

## ٥) خادم VPS

**Nginx** (المسار مثال):
```nginx
server {
    listen 80; server_name hub.example.com;
    root /var/www/lynomia-hub/public;
    index index.php;
    location / { try_files $uri $uri/ /index.php?$query_string; }
    location ~ \.php$ {
        include fastcgi_params;
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
    }
    client_max_body_size 512m;
}
```
**Apache:** `DocumentRoot /var/www/lynomia-hub/public` مع `AllowOverride All` — و`.htaccess` يتكفل بالباقي.

ثم: `composer install --no-dev && composer run setup` وأعط `storage/` و`bootstrap/cache/` صلاحية كتابة لمستخدم الويب.

## ٦) نقل بياناتك من النسخة السابقة (تطبيق React)

1. في تطبيقك القديم: **الإعدادات ← النسخ الاحتياطي ← تنزيل نسخة كاملة (JSON)**.
2. ارفع الملف إلى الخادم ثم:
   ```bash
   php artisan hub:import storage/app/hub-backup.json
   ```
3. سيستورد الأدوار والمستخدمين وكل سجلات الوحدات الـ٥١ بمطابقة الحقول تلقائياً من السجل المركزي.

> ملاحظتان: المستخدمون المستوردون يأتون **بلا كلمات مرور** — عيّنها لهم من صفحة «المستخدمون». والنسخ **المشفرة** (تبدأ بـ`LYB1:`) فكّ تشفيرها أولاً بتنزيل نسخة غير مشفرة من التطبيق.

## ٧) ما يتضمنه هذا الإصدار — وحدوده بصراحة

**موجود:** الوحدات الـ٥١ كاملة بإضافة/تعديل/عرض/حذف/استعادة، بحث وفلترة حالة وترقيم، مراجع بين الوحدات (فردية ومتعددة)، رفع ملفات وصور، وسوم، حقول سرية محجوبة، لوحة تحكم بعدّادات وآخر النشاطات، مستخدمون/أدوار/مصفوفة صلاحيات، سجل تدقيق، إعدادات، إصدارات السجلات، استيراد بياناتك.

**غير موجود بعد (كان في نسخة React، ويُبنى تباعاً حسب أولوياتك):** التقارير المالية المتقدمة (ميزان مراجعة، قوائم)، كانبان ومخططات، لوحة الأوامر، البث اللحظي، الأتمتة والتنبيهات المجدولة، المصادقة الثنائية، تصدير Excel/PDF.

## ٨) أوامر مفيدة


## ٩) بنية المشروع (المهم منها)

```
config/hub.php            ← سجل الوحدات الـ٥١: الجداول والحقول والأنواع والمراجع (قلب النظام)
config/hub_nav.php        ← مجموعات القائمة الجانبية
app/Http/Controllers/Web/ ← ٦ متحكمات: عام للوحدات + دخول/لوحة/مستخدمون/أدوار/تدقيق/إعدادات
app/Models/               ← ٦٢ موديل Eloquent قياسي
app/Traits/               ← بحث LIKE · تدقيق · إصدارات · UUID
resources/views/          ← Blade: تخطيط + عارض حقول عام يخدم كل الوحدات
database/migrations/      ← ٥٥ هجرة MySQL قياسية
database/seeders/         ← الدور والمالك ودليل الحسابات
```

**v2.39.0 — «التدقيق: الجولة الثالثة» — سقف خفي كان يمحو الروابط 🔗**

الجولتان الأخيرتان (أداء ومعمارية + واجهة ووصولية) كشفتا عطلاً صامتاً خطيراً وحزمة إصلاحات:

- 🔁 **إعادة إرسال مزدوجة**: استرجاع الرسائل «العالقة» كان يقيس من **إنشاء** الرسالة لا من **حجزها** — فرسالة أُنشئت قبل ربع ساعة وبدأ تشغيلٌ إرسالها الآن يخطفها التشغيل التالي فيرسلها **مرتين** (تلجرام وبريد وwebhooks). أُضيف ختم لحظة الحجز والاسترجاع يقيس عليه.
- 🧠 **مركز الجودة كان يستهلك ٥٠ ميجابايت** لعشرين ألف عميل (تحميل نماذج كاملة) — صار يقرأ صفوفاً خفيفة (~عُشر الذاكرة) بسقف واضح.
- ⚡ **قائمة اشتراكات Webhooks كانت تُقرأ من القاعدة مع كل كتابة في النظام** — صارت مخبّأة دقيقة وتُنسف فوراً عند أي إنشاء/تعطيل/حذف اشتراك (اختبار يثبت أن الاشتراك الجديد يعمل فوراً لا بعد دقيقة).
- 📉 **الطلبات البطيئة**: المسار كان يحمل معرّف السجل فصار كل صفحة سجل بطيئة صفَّ خطأ مستقل — تُعمَّم المعرّفات الآن (`/m/clients/{id}`) فتُجمَّع فعلاً.
- 🎨 **أصناف CSS كانت مستعملة وغير معرّفة**: تبويبا صندوق الوثائق كانا بلا أي تمييز بصري للمحدد، وزر الحذف في Webhooks لم يكن أحمر رغم صنف `danger` — عُرِّفت كلها (واختبار يمنع تكرارها).

**v2.38.0 — «التدقيق: الجولة الثانية» — أعطال تظهر على MySQL وحده 🐬**

الجولة الثانية ركّزت على ما تُخفيه اختبارات sqlite ويظهر على قاعدتك الحقيقية:

- 🐬 **حرجة — سلسلة التدقيق كانت ستصرخ «معدَّل» على قاعدة سليمة**: عمودا `before`/`after` من نوع `json`، وMySQL **يعيد صياغة** الوثيقة عند تخزينها (مسافات، ترميز يونيكود، ترتيب مفاتيح). فالبصمة المحسوبة عند الكتابة لا تطابق المقروءة، وكان `hub:audit-verify` سيبلّغ عن عبثٍ في **كل سطر** فور النشر على MySQL. **أُصلحت** بتوحيد صياغة الوثيقة قبل البصم (مفاتيح مرتبة، ترميز ثابت) فتتطابق على المحركين — وسجلات سليمة بصياغة مختلفة تُقبل، بينما **تغيير المحتوى الحقيقي ما زال يُكشف** (اختباران يثبتان الأمرين).
- 🐬 **حرجة — تصفير الوضع التجريبي كان سيحذف صفراً على MySQL**: المسح كان يطابق نصاً `%"demo":1%` بينما MySQL يخزّن `{"demo": 1}` بمسافة — فتبقى البيانات الوهمية للأبد وتتضاعف ٣٢ صفاً مع كل «تصفير». **أُصلحت** باستخدام مسار JSON (`meta->demo`) الذي يعمل على المحركين.
- 🐬 **عالية — «أول ظهور» للخطأ كان سيُدهس مع كل تكرار**: `first_seen` من نوع `TIMESTAMP` وهو أول عمود توقيت في الجدول، وMySQL يمنحه ضمنياً `ON UPDATE CURRENT_TIMESTAMP` في الإعداد الشائع للاستضافات — فتضيع أثمن معلومة في الخطأ. حُوّل إلى `DATETIME` بلا سلوك ضمني.
- ⚡ **فهارس ناقصة على استعلامات ساخنة**: تنظيف مفاتيح Idempotency كان يمسح الجدول كاملاً **مع كل كتابة عبر الـ API**، وعامل تسليم Webhooks يمسح جدول التسليمات كل خمس دقائق، وصفحة صندوق الوثائق ترتّب بلا فهرس — أُضيفت ثلاثة فهارس مركّبة.
- 🔁 **إعادة محاولة Webhook الفاشلة كانت تعلق في حالة `sending`**: العامل يحجز الصف بتحديث مباشر، فتصير حالة النموذج مخالفة لما في القاعدة وتُتخطى الكتابة بصمت — فتتأخر الإعادة إلى كنس العشر دقائق وتظهر حالة خاطئة في السجل. **أُصلحت** بكتابة الحالة بالاستعلام مباشرةً.
- 📭 **الاشتراك الموقوف مؤقتاً كان يفقد أحداثه نهائياً**: الإيقاف بعد ١٠ إخفاقات تباعدٌ آلي لا إلغاء اشتراك، فصارت أحداثه **تُصفّ بموعد ما بعد الإيقاف** بدل أن تضيع (أما المعطَّل يدوياً فقرار صريح تُهمل أحداثه — اختباران يميزان الحالتين).
- 🔍 **تصنيف الوثائق**: كتابة `%` كانت تطابق **كل** السجلات فتُربط الوثيقة بسجل عشوائي (محارف LIKE بلا تهريب) — أُصلحت؛ و**التطابق التام صار يفوز** فلم يعد «شركة النور» يُرفض لمجرد وجود «شركة النور الثانية»؛ واشتراك Webhook باسم وحدة مجرد (`clients`) صار يعني كل أحداثها بدل ألا يطابق شيئاً بصمت.
- 📉 **الطلبات البطيئة كانت تُغرق مركز الأخطاء**: المدة بالمللي ثانية كانت داخل هوية التجميع فكل طلب بطيء صفٌّ جديد — صارت **مراتب** (`>ثانية`، `>3ث`، `>10ث`، `>30ث`) فتُعدّ بدل أن تتكاثر، وعتبة البطء صارت قابلة للضبط (`ops.slow_ms`).
- 🧪 الحزمة الآن **٧٠ اختباراً / ٢٥٩ تحققاً**، منها اختبارات تحاكي إعادة صياغة MySQL لوثائق JSON على sqlite فتلتقط هذا الصنف من الأعطال مستقبلاً.
